# 安全に質問・相談するテンプレート

質問前に秘密情報を除きます。パスワード、Token、秘密鍵、個人情報は伏せ字にするのではなく、共有する本文から削除します。

「事実」「推測」「未確認」の見分け方: 事実は自分の目で見た・実際に実行して出た結果、推測はまだ確かめていない考えです。「たぶん」「〜のはず」と思ったら推測、画面に表示された・コマンドで確認した内容だけが事実です。

```text
やりたいこと:
使用環境(OS / WSL・VM / version):
対象が学習用であること: はい / いいえ / 不明
実行したコマンド:
表示されたエラー全文:
期待していた結果:
直前に行ったこと:
自分で確認したこと:
現在の影響:
戻し方 / snapshot:
事実:
推測:
未確認:
秘密情報を削除した: はい / いいえ
```

## 悪い記入例（推測を事実として書いてしまった）

```text
やりたいこと: 学習用VMのWeb serviceに接続したい
使用環境: Ubuntu 24.04 / NAT接続のVM
実行したコマンド: curl http://192.0.2.10
表示: curl: (7) Failed to connect to 192.0.2.10 port 80: Connection refused
期待: ページが表示される
直前操作: serviceの起動手順を実施
確認: とくになし
影響: 学習用VMだけ
戻し方: 未確認
事実: Firewallが原因で接続できない
推測: (空欄)
未確認: (空欄)
秘密情報を削除した: はい
```

まだ`ss -lntp`やFirewall設定を確認していないのに、「Firewallが原因」と事実欄に書いてしまっています。これは自分の目で見た結果ではなく考え(推測)なので、本来は次のように分けて書きます。

```text
事実: curlがConnection refusedで失敗した
推測: Firewallまたはserviceの停止が原因ではないか
未確認: serviceの起動状態、Firewallの許可設定
```

## 良い相談の例

```text
やりたいこと: 学習用Ubuntu VMのWeb service状態を確認したい
使用環境: Ubuntu 24.04 / NAT接続のVM
実行したコマンド: systemctl status example.service
表示: Unit example.service could not be found.
期待: activeと表示される
直前操作: package導入手順の3番まで実施
確認: pwd、コマンドの綴り、導入済みpackage一覧
影響: 学習用VMだけ。外部利用者なし
戻し方: clean-install snapshotあり
事実: unitが見つからない / 推測: package名を誤った可能性 / 未確認: 正しいunit名
秘密情報を削除した: はい
```

「動きません」だけでなく、相手が同じ状況を再現し、次の確認を1つ選べる情報を渡すことが目的です。
