本人がWSL Ubuntuでsummarize-log.shを作成し、人工サンプルと存在しないファイルを使って4通りの判定を確認しました。AIが手順を案内し、本人が提示した端末画像を読み取って公開用要約を作成しています。AIの代理実行やCIによる実測ではありません。

[失敗0件と空ログ](./cli-log-count-empty-2026-09-14.md)、[読み取りエラー](./cli-log-read-error-2026-09-14.md)の確認を、判定メッセージと終了コードを返すスクリプトへまとめた追加演習です。

## 作成した処理

次は会話で案内したコードです。本人がファイル保存・構文確認と後述の4試験を行ったことを画面で確認しました。ローカル原本の取得やハッシュ照合は行っていません。

```bash
#!/usr/bin/env bash

if [ "$#" -ne 1 ]; then
  echo "使い方：bash summarize-log.sh ログファイル" >&2
  exit 2
fi
log_file="$1"

total=$(grep -cE '^スクリプト終了コード=[0-9]+$' -- "$log_file")
search_status=$?

if [ "$search_status" -gt 1 ]; then
  echo "集計不能：読み取りエラー" >&2
  exit 2
elif [ "$search_status" -eq 1 ]; then
  echo "判定保留：集計対象の記録がありません"
  exit 3
fi

failed=$(grep -cE '^スクリプト終了コード=[1-9][0-9]*$' -- "$log_file")
search_status=$?

if [ "$search_status" -gt 1 ]; then
  echo "集計不能：失敗件数を読み取れません" >&2
  exit 2
fi

printf '全件数=%s 失敗件数=%s\n' "$total" "$failed"

if [ "$failed" -gt 0 ]; then
  echo "判定：失敗記録あり"
  exit 1
else
  echo "判定：集計対象内に失敗記録なし"
  exit 0
fi
```

grepの結果を直後に保存し、読み取りエラー・対象行なし・失敗あり・失敗なしを分けます。スクリプトの終了コードは、この処理で定義した値であり、grep自身の終了コードと同じ意味ではありません。

## 本人が実施した試験

新しい検証用フォルダと、終了コード0を2行含むsuccess-only.log、0と22を含むmixed.log、空のempty.logを作成しました。準備の各終了コードは0でした。スクリプト保存とbash -nによる構文確認も終了コード0でした。

| 入力 | 集計・表示 | スクリプト終了コード |
| --- | --- | --- |
| 正常のみの人工サンプル | 全2件・失敗0件、集計対象内に失敗記録なし | 0 |
| 失敗を含む人工サンプル | 全2件・失敗1件、失敗記録あり | 1 |
| 空ログ | 判定保留：集計対象の記録がありません | 3 |
| 作成していないnot-created.log | No such file or directory、集計不能：読み取りエラー | 2 |

すべてbash経由で実行しました。入力は人工サンプルであり、正常2件という表示をHTTP成功2回の実績とは扱いません。存在しないファイルの試験のために既存ログを削除したわけでもありません。

## 制約と未実施範囲

- 所定の正規表現に一致する行を数える処理です。記録行の欠落・重複・不正形式を検査していません。正常行と不正行が混ざっていても、正常行だけを集計する可能性があります。
- 終了コード3は「空ファイル専用」ではなく、集計対象行が見つからない場合の判定です。不正形式しかないファイルでの動作は未試験です。
- 全件と失敗件数を別々のgrepで読むため、集計中のログ変更や同時書き込みは未検証です。

- 作成物は学習用のスクリプト・人工サンプル・演習記録です。HTTP接続、nginx設定変更、サービス停止は行っていません。
- 根拠は本人提示画像です。個人環境のIP・ユーザー名・ホスト名・絶対パス、鍵情報、画像、ローカル原本、完全な生ログは公開しません。
