## 状態表示

> **かんたんに言うと** この 4 つのラベルは、書かれている結果がどこまで確かなものかを示す目印です。ラベルを見れば、実際に測った結果か、自動生成か、架空の例か、まだ実施していないかが分かります。

- **MEASURED**: 日時、commit（変更を記録した履歴の目印）、環境、コマンド、結果を伴う実測。
- **CI-GENERATED**: CI（コードを自動で検証する仕組み）の一時 runner（その都度用意され、終わると消える実行用の環境）が自動生成した結果。
- **SAMPLE**: 説明用の架空例。実績に数えない。
- **NOT RUN**: 手順または計画のみで未実施。

## 安全原則

> **かんたんに言うと** ここに並ぶ 5 つは、練習で自分や他人に被害を出さないための約束です。作業を始める前に必ず読みます。

1. 自分が所有していて、いつでも削除できる VM / WSL2 の中だけで行う。失敗しても消してやり直せる場所を選ぶため。
2. SSH（別のパソコンからネットワーク越しに操作する仕組み）や Firewall（通信を通すか止めるかを決める設定）の変更前は、別のセッション（接続中の操作画面）をつないだまま維持する。あわせて、元へ戻す手順も用意する。設定を誤って自分がログインできなくなっても、そこから戻せるようにするため。
3. パスワード、秘密鍵（本人確認に使う秘密のファイル）、Token（サービスを利用するための通行証となる文字列）、実在する IP / hostname（機器の住所にあたる番号と名前）を証跡へ含めない。公開した記録から悪用される危険があるため。
4. 期待外の結果が出たら連続操作せず、時刻、現象、直前操作を記録する。
5. AWS（インターネット越しに借りるサーバーなどのサービス）、外部への通知、長時間の試験は、費用と情報の送信先を先に確認する。そのうえで、実施すると決めてから行う。費用が発生したり、情報が外部へ送られたりする操作のため。
