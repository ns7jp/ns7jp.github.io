# END行の終了コードを検査

実施日：2026年9月15日（JST）

本人がWSL Ubuntuで、[順序検査付きID検査](./cli-id-order-check-2026-09-15.md)にEND行の終了コード検査を追加しました。AIが手順を案内し、本人提示の端末画像を読み取って公開用要約を作成しています。AIの代理実行やCIの実測ではありません。入力は人工サンプルで、新しいHTTP接続は行っていません。

## 修正前の問題と追加処理

START run_id=A、END run_id=Aの2行を作成しました。検索・作業先作成・保存・表示は終了コード0でした。元の検査はcodeがなくてもSTART=1 END=1、終了コード0となり、結果の記録欠落を見落としました。

元のスクリプトを残して別名のcheck-run-ids-code.shを作る手順で進めました。コピー終了コードは提示画像では未確認です。構文確認は0、指定した追加処理の差分を確認しました。awk内のID抽出前に追加したコードは次のとおりです。

```awk
    if ($1 == "END") {
      if (NF != 3 || $3 !~ /^code=(0|[1-9][0-9]*)$/) {
        print "終了コード形式不正：行" NR
        bad=1
        next
      }
      value=substr($3, 6)
      if (value + 0 > 255) {
        print "終了コード範囲外：行" NR
        bad=1
        next
      }
    }
```

END行は空白区切りで3項目、codeは先頭ゼロのない非負整数、値は0〜255とする検査です。掲載コードは案内と差分画像に基づき、ローカル原本の取得・ハッシュ照合は行っていません。

## 本人が確認した結果

各サンプルはSTART run_id=Aに続くEND行の内容を変えて作成しました。

| END行の内容 | 表示結果 | 修正版終了コード |
| --- | --- | --- |
| code指定なし | 行2の終了コード形式不正、START=1 END=0 | 1 |
| code=0 | START=1 END=1 | 0 |
| code=255 | START=1 END=1 | 0 |
| code=256 | 行2の終了コード範囲外、START=1 END=0 | 1 |
| code=ERROR | 行2の終了コード形式不正、START=1 END=0 | 1 |

不正ENDはbadを設定してnextで処理を飛ばすため、表示されるEND件数は0です。ファイル内にENDという行が物理的に存在しないという意味ではなく、有効なENDとして数えなかった結果です。

255は検査で許可した範囲の上限です。検査合格の0は記録の妥当性であり、人工入力のcode=255が処理成功を表すという意味ではありません。
