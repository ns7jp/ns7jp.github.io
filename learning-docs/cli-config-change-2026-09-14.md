# 案件05追加：nginx設定変更の反映と切り戻し

実施日：2026年9月14日（JST）

本人がWSL Ubuntuの練習用nginxへ応答ヘッダーを追加し、応答への反映を確認した後、バックアップから元の設定へ戻しました。AIが手順を案内し、本人が提示した端末画面を読み取って公開用要約を作成しています。AIの代理実行やCIによる実測ではありません。

[9月10日の案件05](./cli-practice-2026-09-10.md)は同じ設定の再読込だけでした。本書は設定変更を伴う追加演習です。[ファイル復元練習](./cli-file-restore-2026-09-14.md)と異なり、今回は稼働中の練習用nginxが参照する設定ファイルを変更・復元し、実際のHTTP応答も確認しました。過去の記録は当時の状態として残します。

## 対象と事前確認

- 対象は本人のWSL内のnginxと、同じWSL内からのHTTP接続です。本番環境や別ホストではありません。
- sites-enabled/defaultが`/etc/nginx/sites-available/default`を指すリンクであることを確認しました。
- 変更前のHTTP応答は200で、X-Practiceヘッダーはありませんでした。curl終了コードは0でした。
- ホーム内に新しい専用フォルダを作成し、sudo cp -pで現行設定を退避しました。作成・コピー・diffは終了コード0、両方の所有者root・グループroot・権限644を確認しました。
- この演習では停止・再起動は指示せず、検査後の再読込で反映し、最後に切り戻す手順を使用しました。

## 変更と応答による検証

有効なserverブロックのserver_name指定の直後に、次の1行を追加しました。

```nginx
add_header X-Practice "case05" always;
```

最初の応答で追加ヘッダーが出ず、その後の再確認で現れた原因は未特定です。再読込のタイミングが原因だったと断定しません。また、HTTP再確認時にヘッダーは取得しましたが本文は破棄したため、変更後ヘッダーと本文を同一レスポンスで確認したという主張はしません。

## 学びと切り戻しの範囲

本人は「元の設定ファイルの内容が反映されないから」と、復元後にも再読込が必要な理由を説明しました。ファイルを戻しただけで完了とせず、動作中のnginxから返るヘッダーが「なし → あり → なし」と変化し、切り戻し後も初期ページを取得できることを確認しました。

バックアップとのdiffは内容一致を確認したものです。所有者・グループ・権限はバックアップ作成時に比較していますが、切り戻し後の全メタデータは再検証していません。
