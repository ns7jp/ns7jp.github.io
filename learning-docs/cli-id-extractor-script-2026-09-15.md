# 検査後の結果抽出をスクリプト化

実施日：2026年9月15日（JST）

本人がWSL Ubuntuでextract-results.shを作成し、検査合格時だけIDとcodeを抽出する処理をファイル化しました。AIが手順を案内し、本人提示の端末画像を読み取って公開用要約を作成しています。AIの代理実行やCIの実測ではありません。

[端末上での検査後抽出](./cli-id-result-extract-2026-09-15.md)に続く演習です。保存済みHTTPログとcode欠落の人工入力を使用し、新しいHTTP接続は行っていません。

## 作成した処理

検査メッセージは標準エラー、抽出結果は標準出力へ分け、検査失敗時はその終了コードを返します。保存とbash -nは終了コード0でした。掲載コードは案内と本人の保存画面に基づき、原本のハッシュ照合は行っていません。

```bash
#!/usr/bin/env bash

if [ "$#" -ne 2 ]; then
  echo "使い方：bash extract-results.sh 検査スクリプト ログ" >&2
  exit 2
fi

checker="$1"
log_file="$2"

if bash "$checker" "$log_file" >&2
then
  awk '$1 == "END" { print $2, $3 }' < "$log_file"
  extract_status=$?
  exit "$extract_status"
else
  validation_status=$?
  echo "検査不合格のため抽出しません：終了コード=$validation_status" >&2
  exit "$validation_status"
fi
```

## 本人が確認した結果

| 入力 | 実行結果 | 保存した出力 |
| --- | --- | --- |
| 保存済みHTTP実行ログ | 検査合格後に2行を抽出、抽出スクリプト終了コード0 | results.txtにIDとcode=0/22、validation.logにID別START/END検査結果 |
| ENDにcodeがない人工サンプル | 形式不正を検出し抽出しない、抽出スクリプト終了コード1 | invalid-results.txtは0バイト、invalid-validation.logに形式不正と抽出中止 |

正常時の両ファイルのcat、不正時のwc -cと検査ログのcatは終了コード0でした。不正サンプルの保存も0でした。

出力先は呼び出し時に`> results.txt 2> validation.log`の形で分離しました。実際のコマンドは専用フォルダ内のパスを指定し、正常・不正の出力先を別名にしました。不正時もシェルが結果ファイルを開くため空ファイルは存在しますが、抽出データは0バイトでした。空の結果ファイルだけで成功とせず、スクリプト終了コード1と検査メッセージを併せて判断しました。
