# CUIの最初の30分

> **かんたんに言うと** キーボードで文字の命令を打ってパソコンを動かす操作（CUI）を、30分でひととおり体験する練習ページです。

上から1行ずつ順に実行していく、Linux（リナックス。サーバーでよく使われる基本ソフト）とWSL2（ウィンドウズの中でLinuxを動かす仕組み）向けの、いちばん短い演習です。画面に出ている `$` は、入力を待っている合図（プロンプト）です。`$` そのものは入力しません。この演習はホームディレクトリ（利用者ごとに割り当てられた自分専用の作業場所）で行います。別の場所へ移動している場合は、そのまま始めないでください。

## 0〜5分 — 自分と場所を確認

目的: 作業を始める前に「今の自分は誰として、どの環境の、どこにいるのか」を確かめます。この3つを毎回答えられれば、操作する場所を取り違えていないと説明できます。

```bash
whoami
hostname
pwd
```

**表示の意味:** `whoami` は、今ログインしているユーザー名を表示します。`hostname` は、今使っているコンピューター（環境）の名前を表示します。`pwd` は、今いる場所（現在のディレクトリ）を表示します。`pwd` の表示が `/home/<自分のユーザー名>` でない場合は、`cd` だけを入力して実行します。`cd` のうしろに何も付けない（引数を付けない）と、ホームディレクトリに戻ります。その後もう一度 `pwd` を実行して確認します。

## 5〜15分 — 学習用ファイルを作る

目的: 練習用のディレクトリを1つ作り、その中だけで作業します。場所を分けておけば、失敗しても手元の大事なファイルに影響しません。

```bash
mkdir cui-practice
cd cui-practice
printf '%s\n' 'first practice' > note.txt
cat note.txt
```

**各行の意味:** `mkdir cui-practice` は、`cui-practice` という名前のディレクトリ（フォルダ）を作ります。`cd cui-practice` は、その中へ移動します。`printf` の行は、`first practice` という1行を `note.txt` に書き込みます。`cat note.txt` は、ファイルの中身を画面に表示します。

**期待結果:** `cat` の次の行に `first practice` と表示されます。`>` は、書き込み先のファイルの中身をすべて置き換える（上書きする）記号です。もともとあった内容は残りません。だからこの演習では、今作った `note.txt` だけに使います。

出力例（架空値。実測ではありません。実際に動かして測った結果ではなく、説明のために用意した例です）:

```text
$ cat note.txt
first practice
```

## 15〜20分 — コピーして違いがないか確認

```bash
cp note.txt note-backup.txt
ls -la
cmp note.txt note-backup.txt
echo $?
```

**期待結果:** `ls -la` の一覧に2つのファイルが並びます。`cmp` は2つのファイルの中身を1文字ずつ比べるコマンドで、まったく同じなら何も表示しません。`echo $?` の `$?` は直前のコマンドの終了コードを指す書き方で、ここでは `0` が表示されます。終了コードとは、直前のコマンドが成功したか(0)失敗したか(0以外)を示す数字です。表示がないことだけで成功と決めず、終了コードでも確認します。ここまで確認できれば、「コピーした `note-backup.txt` は元の `note.txt` と中身が同じだと確かめた」と説明できます。

出力例（架空値。実測ではありません）:

```text
$ ls -la
total 12
drwxr-xr-x 2 example-user example-user 4096 Sep  1 09:00 .
drwxr-xr-x 3 example-user example-user 4096 Sep  1 09:00 ..
-rw-r--r-- 1 example-user example-user   15 Sep  1 09:00 note-backup.txt
-rw-r--r-- 1 example-user example-user   15 Sep  1 09:00 note.txt
$ cmp note.txt note-backup.txt
$ echo $?
0
```

## 20〜25分 — 証拠を残す

> **かんたんに言うと** いくつかのコマンドの結果を、まとめて1つのファイルに書き出します。

目的: あとから「いつ、誰が、どこで、何をしたか」を人に見せられるように記録を残します。`{` と `}` で囲んだ範囲は、ひとまとまりの処理として扱われます。そのまとまりの表示すべてを、`>` で `practice-result.txt` に書き込みます。`date -Is` は、決まった書式で日付と時刻を表示するコマンドです。

```bash
{
  date -Is
  whoami
  hostname
  pwd
  ls -la
} > practice-result.txt
cat practice-result.txt
```

**期待結果:** `practice-result.txt` の中に、時刻・ユーザー名・環境名・現在地・ファイル一覧がまとめて入ります。`cat` でその中身を確認します。この記録を人に見せたり公開したりするときは、ユーザー名や環境名を伏せます。名前や環境名は、他人が環境を推測する手がかりになるためです。

## 25〜30分 — 対象を確認して片付ける

> **かんたんに言うと** 消してよいものだけかを先に目で確かめてから、練習用のディレクトリを削除します。

目的: `rm` で消したファイルは元に戻せません。だからいきなり消さず、`find` で対象を確かめてから削除し、最後に本当に消えたかを確認します。この順番は、実際の運用でも同じです。

```bash
cd ..
pwd
find cui-practice -maxdepth 1 -type f -print
rm -rI cui-practice
test ! -e cui-practice
echo $?
```

`find` の各オプションは次の意味です。

- `-maxdepth 1`: `cui-practice` の直下だけを調べ、それより深い階層は見ない
- `-type f`: 通常ファイルだけを対象にし、ディレクトリは含めない
- `-print`: 見つかったパスを1行ずつ表示する

削除と確認のコマンドは、次の意味です。

- `rm -rI cui-practice`: `-r` はディレクトリの中身ごと削除する指定、`-I` は削除の前に一度だけ確認を求める指定です
- `test ! -e cui-practice`: `cui-practice` が存在しないことを確かめます。存在しなければ終了コードは `0` になります

まず、`find` の一覧がこの演習で作った3ファイルだけであることを確認します。確認できたら `rm -rI cui-practice` を実行します。すると、次のような確認メッセージ（プロンプト）が表示されます。表示されるファイル数は環境により変わることがあります。

```text
rm: remove 3 files in directory 'cui-practice'?
```

ここで `y` と入力すると削除を実行し `cui-practice` は消えます。`n` と入力すると削除を中止し、`cui-practice` はそのまま残ります。内容に確信が持てないときは `n` を選び、もう一度 `ls -la cui-practice` などで確認します。最後の `echo $?` が `0` を表示すれば、学習用ディレクトリはなくなっています。ここまで実行できれば、「消す前に対象を確認し、消えたあとも確認した」と面接や報告で説明できます。

## 違う結果になったら

うまくいかないときは、次のコマンドを続けて試さないでください。原因が分からないまま操作を重ねると、状態がさらに変わって切り分けが難しくなります。まず、自分が入力した行とエラーメッセージの全文を、そのまま保存します。`Permission denied`（権限がない）、`command not found`（コマンドが見つからない）、`No such file or directory`（そのファイルやディレクトリがない）は[初心者向けエラーFAQ](./beginner-troubleshooting.md)で確認します。完了したら[CUIマニュアル](../cui-manual.html)の段階演習へ進みます。
