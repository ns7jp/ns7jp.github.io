# 権限不足による集計不能と復旧

実施日：2026年9月14日（JST）

本人がWSL Ubuntuで練習用ログの読み取り権限を外し、形式検査付き集計スクリプトが集計不能を返すことを確認しました。その後、権限を戻して集計できる状態へ復旧しました。AIが手順を案内し、本人が提示した端末画像を読み取って公開用要約を作成しています。AIの代理実行やCIの実測ではありません。

対象は[形式検査付き集計](./cli-log-format-check-2026-09-14.md)のsummarize-log-checked.shと、新しく作成した人工サンプルです。[存在しないファイルの読み取りエラー](./cli-log-read-error-2026-09-14.md)に続き、今回はファイルが存在していても読めない場合を試しました。

## 本人が実施した操作と結果

| 段階 | 操作 | 提示画面で確認した結果 |
| --- | --- | --- |
| 準備 | 修正版検索、新規フォルダ作成、sample.log保存、catで読み取り | 各終了コード0。内容はスクリプト終了コード=0の1行、権限644 |
| 権限変更 | chmod u-rで所有者の読み取り権限を外す | 変更終了コード0、権限表示は--w-r--r--（244） |
| 集計試行 | 一般ユーザーで修正版を実行 | awkがPermission denied、集計不能：形式検査でエラー、スクリプト終了コード2 |
| 権限復元 | chmod u+rで所有者の読み取り権限を戻す | 復元終了コード0、権限表示は-rw-r--r--（644） |
| 再集計 | 同じ修正版と同じサンプルで実行 | 全1件・失敗0件、失敗記録なし、スクリプト終了コード0 |
| 記録保存 | 本人が演習要約を保存し、catで再表示 | 保存終了コード0と記録内容を確認 |

集計にはsudoを付けず、ファイル所有者である一般ユーザーで実行しました。グループ・その他の読み取り権限が残っていても、今回の所有者には所有者の権限が適用され、読み取りは拒否されました。

変更対象は今回の練習用sample.logだけです。実際のHTTP実行履歴、nginxの設定やサービス状態は変更していません。

## 判断と理解確認

権限がない間は内容を読めず、失敗件数は不明です。ファイルの存在や、事前に内容を知っていたことを理由に、読めなかった集計結果を失敗0件とは扱いません。権限復元後は、実際に読み取り・集計できた結果として全1件・失敗0件を確認しました。

本人は理解確認で「読み取り権限がないと、失敗しているかどうかわからないから」と説明しました。支援なしの独立再実施は未確認です。

本人がWSL内にlog-permission-2026-09-14.txtを保存し、保存終了コード0と内容の再表示を提示しました。
