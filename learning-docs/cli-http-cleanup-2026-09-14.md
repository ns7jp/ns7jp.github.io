# HTTP本文判定スクリプトの一時ファイル後始末

実施日：2026年9月14日（JST）

本人がWSL Ubuntuで、check-http-body.shの終了時に一時ファイルが残らないことを3通りで確認しました。AIが手順を案内し、本人が提示した端末画像を読み取って公開用要約を作成しています。AIの代理実行やCIによる実測ではありません。

[前回の本文判定演習](./cli-http-body-check-2026-09-14.md)では、trapによる削除処理は実装済みでしたが、削除後の状態は未確認でした。本書はその追加検証です。前回の記録は当時の状態として残します。

## 検証方法

1. findで既存のcheck-http-body.shを1件確認（検索終了コード0）。
2. mktemp -dで新しい検証用フォルダを作成（終了コード0）。
3. TMPDIRにそのフォルダを指定し、既存スクリプトをbash -xで実行。
4. 実行トレースで一時ファイルの生成先、exit、同じファイルへのrm実行を確認。
5. 各実行後に検証用フォルダ直下をfindで一覧表示し、残存がないことを確認。

スクリプト自体は変更していません。既存の処理はmktempで本文保存先を作成し、次のtrapを登録していました。

```bash
trap 'rm -f -- "$body_file"' EXIT
```

TMPDIRは各実行にだけ指定しました。トレースでは生成先が今回の検証用フォルダ内であることを確認しています。残存確認は`find "$cleanup_dir" -mindepth 1 -maxdepth 1 -print`で行いました。findの終了コード0だけでなく、出力行がないことも確認しました。

## 本人が確認した結果

| 実行条件 | 応答・判定 | スクリプト終了コード | トレースと終了後の状態 |
| --- | --- | --- | --- |
| 正常なページ・期待する文字列あり | HTTP 200、本文一致 | 0 | exit 0の後に対象一時ファイルへのrm。find表示なし・終了コード0 |
| 同じページ・存在しない文字列を指定 | HTTP 200、本文不一致 | 1 | exit 1の後に対象一時ファイルへのrm。find表示なし・終了コード0 |
| 存在しないページ | HTTP 404、HTTP取得失敗 | 22 | exit 22の後に対象一時ファイルへのrm。find表示なし・終了コード0 |

正常時は期待する文字列を含む本文の行も表示されました。本文不一致では検索結果1、404ではcurl結果22を保存して返す処理がトレースに出ています。いずれも削除処理の後、呼び出し元が受け取ったスクリプトの終了コードは0・1・22でした。

検証用フォルダ自体は残し、その中の一時ファイルが残っていないことを確認しました。rmの表示だけで削除成功を断定したのではなく、続くfindの結果と合わせて判断しています。
