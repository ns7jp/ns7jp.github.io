# 安全に質問・相談するテンプレート

> **かんたんに言うと** 質問するときに書く内容をあらかじめ決めた「型」です。この型どおりに書くと、相手が状況を思い浮かべやすくなり、答えが早く返ってきます。

質問する前に、秘密情報を本文から取り除きます。秘密情報とは、パスワード、トークン、秘密鍵、個人情報などです。トークン（Token）は、本人確認の代わりに使う長い文字列で、鍵と同じ働きをします。秘密鍵は、暗号通信で本人であることを証明するファイルです。これらは伏せ字（一部を`*`などで隠す書き方）にするのではなく、共有する本文から削除します。削除する理由は、秘密情報が他人の手に渡ると、環境に勝手に入られる恐れがあるからです。

「事実」「推測」「未確認」の見分け方を説明します。事実とは、自分の目で見た結果や、実際に実行して出た結果です。推測とは、まだ確かめていない自分の考えです。未確認とは、まだ見ていない・まだ調べていない項目です。「たぶん」「〜のはず」と思ったら、それは推測です。画面に表示された内容や、コマンドで確認した内容だけが事実です。この3つを分けて書くと、相手は事実だけを手がかりにできるため、見当違いの回答を減らせます。

次のテンプレートをコピーして、上から順に埋めます。

```text
やりたいこと:
使用環境(OS / WSL・VM / version):
対象が学習用であること: はい / いいえ / 不明
実行したコマンド:
表示されたエラー全文:
期待していた結果:
直前に行ったこと:
自分で確認したこと:
現在の影響:
戻し方 / snapshot:
事実:
推測:
未確認:
秘密情報を削除した: はい / いいえ
```

テンプレートに出てくる言葉を補足します。OSは基本ソフトで、WindowsやUbuntuのように機械全体を動かす土台のソフトです。WSLは、Windowsの中でLinuxを動かす仕組みです。VMは仮想マシンで、1台のパソコンの中に作る、もう1台の仮想のパソコンです。versionは版数で、そのソフトが何回目の改訂かを表す番号です。snapshotは、ある時点の状態を丸ごと保存したものです。「対象が学習用であること」を書くのは、本番で使っている環境かどうかで、相手がすすめられる対処が変わるためです。「現在の影響」と「戻し方 / snapshot」を書くと、失敗しても元へ戻せる状態かどうかが相手に伝わります。

## 悪い記入例（推測を事実として書いてしまった）

> **かんたんに言うと** 次の例は、まだ確かめていないことを「事実」の欄に書いてしまった悪い例です。真似する見本ではなく、どこが事実でどこが自分の考えかを見分ける練習として読みます。

```text
やりたいこと: 学習用VMのWeb serviceに接続したい
使用環境: Ubuntu 24.04 / NAT接続のVM
実行したコマンド: curl http://192.0.2.10
表示: curl: (7) Failed to connect to 192.0.2.10 port 80: Connection refused
期待: ページが表示される
直前操作: serviceの起動手順を実施
確認: とくになし
影響: 学習用VMだけ
戻し方: 未確認
事実: Firewallが原因で接続できない
推測: (空欄)
未確認: (空欄)
秘密情報を削除した: はい
```

はじめに、例の中に出てきた言葉を補足します。`curl`は、指定した場所へ通信して結果を表示するコマンドです。`Connection refused`は「接続を拒否された」という意味の表示です。NAT接続は、仮想マシンがパソコン本体の通信を借りて外へつなぐ方式です。この例では、まだ`ss -lntp`（通信を待ち受けているプログラムの一覧を表示するコマンド）や、ファイアウォール（Firewall。決めた条件で通信を許可・拒否する関所）の設定を確認していません。それなのに、「Firewallが原因」と事実欄に書いてしまっています。これは自分の目で見た結果ではなく、自分の考え（推測）です。事実の欄に推測を書くと、相手はそれを確かめ済みの情報だと思い込み、見当違いの回答をしてしまいます。本来は、次のように事実と推測を分けて書きます。

```text
事実: curlがConnection refusedで失敗した
推測: Firewallまたはserviceの停止が原因ではないか
未確認: serviceの起動状態、Firewallの許可設定
```

なお、service（サービス）とは、画面に出ないまま背景で動き続けるプログラムのことです。このように書くと、「接続を拒否されたところまでは確認できた。原因はまだ特定できていない」と自分の言葉で説明できます。相手も、次に何を確認すればよいかを1つ選びやすくなります。

## 良い相談の例

> **かんたんに言うと** 次の例は、事実・推測・未確認が分かれていて、相手がそのまま同じ状況を作り直せる良い例です。埋め方の見本として読みます。

例に出てくる言葉を補足します。`systemctl`は、サービスの起動や停止、状態の確認を行うコマンドです。unit（ユニット）は、systemctlが扱うサービス1つ分の設定のまとまりです。package（パッケージ）は、ソフトを導入するためのひとまとまりの部品です。clean-install snapshotは、導入した直後のきれいな状態を保存しておいたものです。

```text
やりたいこと: 学習用Ubuntu VMのWeb service状態を確認したい
使用環境: Ubuntu 24.04 / NAT接続のVM
実行したコマンド: systemctl status example.service
表示: Unit example.service could not be found.
期待: activeと表示される
直前操作: package導入手順の3番まで実施
確認: pwd、コマンドの綴り、導入済みpackage一覧
影響: 学習用VMだけ。外部利用者なし
戻し方: clean-install snapshotあり
事実: unitが見つからない / 推測: package名を誤った可能性 / 未確認: 正しいunit名
秘密情報を削除した: はい
```

「動きません」とだけ伝えても、相手は状況を思い浮かべられません。相手が同じ状況を再現でき、次に確認することを1つ選べる情報を渡すことが、このテンプレートの目的です。ここまで書けると、「原因はまだ分からないが、どこまで確認できたかは説明できる」と人に伝えられる状態になります。
