## 出力と終了コードの保存方法

本人は次の順序で実行しました。以下は今回の操作を説明する抜粋です。body_scriptは確認済みの実行ファイル、run_dirは新しく作成したログ用フォルダを指します。これらの変数の準備を省略しているため、そのまま実行する完全な手順ではありません。

```bash
date -Is > "$run_dir/success.log"
bash "$body_script" "http://127.0.0.1/" >> "$run_dir/success.log" 2>&1
run_status=$?
printf 'スクリプト終了コード=%s\n' "$run_status" >> "$run_dir/success.log"
cat "$run_dir/success.log"
```

失敗時は存在しないページのURLとfailure.logを使用しました。通常の出力先をログへ指定した後に2>&1を置き、標準エラー出力も同じログへ向けています。実際にcurlのエラーメッセージがfailure.logの再表示で確認できました。

スクリプト実行の直後にrun_status=$?で結果を保持しています。後続のprintfやcatの成功を、HTTP確認の成功と混同しません。404時も、処理結果は22、ログへの追記と表示の結果は0でした。

最初のdateは単一の実行記録を開始するためにファイルを作成・上書きします。その後の出力と終了コードを追記しました。今回は新しいフォルダ内で正常・失敗を各1回記録しており、同じログを繰り返し使った場合の履歴保持を検証したわけではありません。日時は実行前に記録した値であり、終了時刻や所要時間は計測していません。

## 理解確認と保存

本人は最初、2>&1の目的が分からないと回答しました。AIの説明後、「エラーメッセージも、通常の出力と同じログファイルへ保存するため」と説明しました。支援なしでの独立再実施は未確認です。

本人がWSL内にhttp-run-log-2026-09-14.txtを保存し、保存終了コード0と記録内容の再表示を確認しました。実行ログのsuccess.log・failure.logと、この演習要約の保存確認は別々に行っています。
