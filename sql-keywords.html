SQL Guide初心者向けSQL文・キーワード集

SQLは「データベースへお願いを伝える言葉」です

SQL（Structured Query Language）は、データベースに対して「見せて」「追加して」「直して」「削除して」と依頼するための言語です。サーバー構築・運用では、アプリの接続確認、監視データの調査、障害時の切り分け、バックアップ後の確認でも使います。

最初の覚え方：読む SELECT → 絞る WHERE → 並べる ORDER BY → 集計する GROUP BY → つなぐ JOIN → 変更する INSERT / UPDATE / DELETE の順で練習します。

DQL：読む

SELECT で必要な行と列を取得します。調査は原則ここから始めます。

DML：データを変える

INSERT / UPDATE / DELETE で行を追加・更新・削除します。

DDL：器を作る

CREATE / ALTER / DROP でテーブルなどの構造を管理します。

DCL：権限を守る

GRANT / REVOKE で「誰が何をできるか」を制御します。

TCL：変更をまとめる

COMMIT / ROLLBACK で変更の確定・取り消しを行います。

運用：速さと安全を確かめる

EXPLAIN、インデックス、ログ、バックアップを組み合わせて確認します。

SQL方言に注意：MySQL、PostgreSQL、SQLite、SQL Serverでは、日付関数、自動採番、文字列結合、件数制限などの書き方が異なります。このページは共通的な書き方を中心にし、実行時は利用製品の公式資料で確認します。

練習用テーブル：servers

以降は、サーバー台帳を想定した次の列を使います。1行が1台のサーバー、列がその属性です。

練習用serversテーブルの列

1. データを読む・絞る・並べる

取得

SELECT

表示したい列を指定します。* は全列ですが、実務では必要な列を明示すると意図が伝わり、不要な転送も減らせます。

対象

FROM

どのテーブルから読むかを指定します。SELECT hostname FROM servers のように使います。

条件

WHERE

条件に合う行だけに絞ります。文字列は通常シングルクォートで囲みます。

並び替え

ORDER BY

ASC は昇順、DESC は降順です。省略時は通常 ASC です。

重複除外

DISTINCT

重複する結果を1つにまとめます。環境名の一覧取得などに使います。

件数制限

LIMIT

返す行数を制限します。MySQL・PostgreSQL・SQLiteで利用できます。SQL Serverは TOP などを使います。

SELECT hostname, role, cpu_usage
FROM servers
WHERE environment = 'prod' AND cpu_usage >= 80
ORDER BY cpu_usage DESC
LIMIT 10;

読む順番：「本番環境でCPU 80%以上のサーバーを、使用率が高い順に最大10台表示」と日本語へ戻せれば理解できています。

よく使う条件：=、<>（等しくない）、AND、OR、NOT、IN (...)、BETWEEN A AND B、LIKE 'web-%'、IS NULL。NULL は値がない状態なので = NULL ではなく IS NULL を使います。

2. 数える・まとめる

集計関数

COUNT / SUM

COUNT(*) は行数、SUM(column) は合計を求めます。

集計関数

AVG / MIN / MAX

平均・最小・最大を求めます。監視値の傾向確認に便利です。

グループ

GROUP BY

同じ値ごとに行をまとめます。環境別・役割別の台数集計に使います。

集計後の条件

HAVING

WHERE は集計前の行、HAVING は集計後のグループを絞ります。

別名

AS

列やテーブルへ分かりやすい別名を付けます。AS server_count のように使います。

条件分岐

CASE

値に応じて表示を変えます。CPU使用率を「正常・警告・異常」に分類できます。

SELECT environment, COUNT(*) AS server_count, AVG(cpu_usage) AS avg_cpu
FROM servers
GROUP BY environment
HAVING AVG(cpu_usage) >= 60
ORDER BY avg_cpu DESC;

3. 複数のテーブルをつなぐ

servers.owner_id と owners.owner_id のような共通のキーを使って、分けて保存したデータを結びます。

一致行

INNER JOIN

両方のテーブルに一致する行だけを返します。

左側を全件

LEFT JOIN

左側をすべて返し、右側に一致がなければ右側の列は NULL になります。担当未設定の発見に便利です。

結合条件

ON

どの列同士を一致させるかを書きます。条件不足は行数の異常な増加につながります。

SELECT s.hostname, s.environment, o.owner_name
FROM servers AS s
LEFT JOIN owners AS o ON s.owner_id = o.owner_id
WHERE s.environment = 'prod';
確認点：結合前後の件数を比べます。想定より増えた場合は、結合キーの重複や ON 条件不足を疑います。

4. データを追加・更新・削除する

追加

INSERT INTO

新しい行を追加します。列名と値の対応を明示します。

更新

UPDATE / SET

既存行の値を変更します。WHERE がないと全行更新になるため要注意です。

削除

DELETE FROM

行を削除します。WHERE がないと全行削除になります。

INSERT INTO servers (server_id, hostname, role, environment, cpu_usage)
VALUES (104, 'web-02', 'web', 'dev', 15.2);

UPDATE servers
SET last_checked_at = CURRENT_TIMESTAMP
WHERE server_id = 104;

DELETE FROM servers
WHERE server_id = 104 AND environment = 'dev';
安全手順：変更前に同じ WHERE を使った SELECT で対象件数と内容を確認し、可能ならトランザクション内で実行します。本番では承認、バックアップ、切り戻し手順、作業ログも必要です。

5. テーブルと制約を定義する

作成

CREATE TABLE

テーブル名、列名、データ型、制約を定義します。

変更

ALTER TABLE

列や制約を追加・変更します。製品によって対応範囲が異なります。

構造削除

DROP TABLE

テーブル構造とデータを削除します。復旧が難しい破壊的操作です。

主キー

PRIMARY KEY

各行を一意に識別します。重複と NULL を許しません。

外部キー

FOREIGN KEY

別テーブルのキーを参照し、存在しない担当者IDなどを防ぎます。

値の規則

NOT NULL / UNIQUE / CHECK / DEFAULT

必須、重複禁止、条件、初期値をデータベース側で守ります。

CREATE TABLE servers (
    server_id INTEGER PRIMARY KEY,
    hostname VARCHAR(100) NOT NULL UNIQUE,
    role VARCHAR(30) NOT NULL,
    environment VARCHAR(10) NOT NULL CHECK (environment IN ('dev', 'stg', 'prod')),
    cpu_usage DECIMAL(5,2) DEFAULT 0,
    last_checked_at TIMESTAMP
);

6. トランザクションで変更をひとまとまりにする

複数の変更を「すべて成功」または「すべて取り消し」にする仕組みです。途中だけ反映される不整合を防ぎます。

BEGIN;

UPDATE servers SET environment = 'prod' WHERE server_id = 104;
SELECT server_id, hostname, environment FROM servers WHERE server_id = 104;

-- 問題なければ確定
COMMIT;
-- 問題があれば COMMIT の代わりに ROLLBACK;
ACIDの短い覚え方：全部かゼロか（原子性）、ルールを守る（一貫性）、同時作業を分離する（独立性）、確定後は残る（永続性）。DDLが暗黙に確定されるかなどは製品ごとに確認します。

7. 権限と安全なSQL

付与

GRANT

読み取りなど必要な権限だけを付与します。最小権限の原則を守ります。

取り消し

REVOKE

不要になった権限を取り消します。退職・異動・役割変更時も見直します。

安全な入力

プレースホルダー

利用者入力をSQL文字列へ直接連結せず、プリペアドステートメントを使ってSQLインジェクションを防ぎます。

GRANT SELECT ON servers TO monitoring_user;
REVOKE UPDATE, DELETE ON servers FROM monitoring_user;

-- アプリ側の考え方（記法はライブラリで異なる）
SELECT hostname FROM servers WHERE server_id = ?;
秘密情報：パスワードや接続文字列をSQLファイル、ソースコード、Gitへ直接書きません。環境変数や秘密情報管理機能を使い、漏えい時は認証情報をローテーションします。

8. インデックス・ビュー・実行計画

検索補助

CREATE INDEX

本の索引のように検索を速くします。ただし容量を使い、追加・更新・削除が遅くなることがあります。

仮想表

CREATE VIEW

よく使う問い合わせに名前を付けます。複雑さを隠せますが、必ず高速になるわけではありません。

計画確認

EXPLAIN

全件走査か、どのインデックスを使うか、結合順などを確認します。実行を伴う形式は負荷に注意します。

CREATE INDEX idx_servers_environment_role
ON servers (environment, role);

EXPLAIN
SELECT hostname FROM servers
WHERE environment = 'prod' AND role = 'web';
  1. 遅いSQL、実行時間、頻度、対象時間帯をログで特定する。
  2. EXPLAIN で実行計画と推定件数を確認する。
  3. 不要な列・行、関数、並び替え、結合条件を見直す。
  4. 必要なら候補インデックスを検証環境で比較する。
  5. 変更前後の時間、CPU、I/O、ロック、書き込み性能を記録する。

10. サーバー運用でSQLエラーが起きたとき

  1. 影響を確認：誰が、いつから、どの画面・処理で失敗しているかを記録する。
  2. 接続を確認：DBサービス、待受ポート、DNS、Firewall、接続先、TLS、認証を確認する。
  3. エラーを保存：画面だけで判断せず、時刻、SQLSTATE、DBログ、アプリログを採取する。秘密情報は伏せる。
  4. 切り分け：構文、権限、ロック、容量、接続数、タイムアウト、実行計画、直前変更を順に確認する。
  5. 変更を管理：本番で思いつきのSQLを実行せず、承認、対象確認、バックアップ、切り戻し、作業記録をそろえる。
  6. 復旧後を確認：エラーが消えたことだけでなく、件数、整合性、監視、再発有無を確認し、手順へ反映する。
「接続できない」ときの代表例

DBサービス停止、ホスト名・ポート間違い、Firewall遮断、接続元制限、証明書期限、ユーザー停止、パスワード変更、接続数上限を確認します。

「遅い」ときの代表例

全件走査、インデックス不足、統計情報、ロック待ち、同時実行数、CPU・メモリ・ディスクI/O、ネットワーク、データ急増を確認します。

「更新できない」ときの代表例

権限、読み取り専用、制約違反、データ型、トランザクション、デッドロック、ディスク満杯、レプリカ接続を確認します。

11. 手を動かす演習

最初は本番データではなく、SQLiteなどの使い捨て学習環境で実行してください。各演習は「実行SQL・期待結果・実際の結果・気づき」を記録します。

演習1：安全に読む

本番環境のサーバー名と役割を、サーバー名順で最大20件取得してください。

解答例
SELECT hostname, role
FROM servers
WHERE environment = 'prod'
ORDER BY hostname ASC
LIMIT 20;

演習2：集計する

環境ごとのサーバー台数と平均CPU使用率を求めてください。

解答例
SELECT environment, COUNT(*) AS server_count,
       AVG(cpu_usage) AS avg_cpu
FROM servers
GROUP BY environment;

演習3：未設定を探す

LEFT JOIN を使い、担当者が設定されていないサーバーを探してください。

解答例
SELECT s.hostname
FROM servers AS s
LEFT JOIN owners AS o ON s.owner_id = o.owner_id
WHERE o.owner_id IS NULL;

演習4：更新前確認

server_id 104の環境を変更する前に、対象を確認するSQLを書いてください。

解答例
SELECT server_id, hostname, environment
FROM servers
WHERE server_id = 104;

演習5：失敗を調べる

「アプリからDBへ接続できない」場合の確認順を、接続先、ネットワーク、認証、ログの観点で説明してください。

演習6：説明する

WHERE と HAVING、DELETE と DROP の違いを、初学者へ1文ずつ説明してください。

完了条件：SQLが動くだけでなく、対象件数を予測し、結果を確認し、危険な操作と製品差を説明できたら合格です。
