# ID検査の読み取りエラーを区別

実施日：2026年9月15日（JST）

本人がWSL Ubuntuで、[ID検査スクリプト](./cli-run-id-check-2026-09-15.md)のファイル読み取り失敗を試し、件数不整合と同じ終了コード1になることを確認しました。別名の修正版でファイルを開く失敗を2として扱い、4通りを検証しました。AIが手順を案内し、本人提示の端末画像を読み取って公開用要約を作成しています。AIの代理実行やCIの実測ではありません。

## 問題の再現と修正

既存スクリプトはawkへの入力を末尾の`< "$1"`で指定していました。新しい検証フォルダ内の作成していないnot-created.logを渡すと、No such file or directoryと終了コード1になりました。終了コードだけでは件数不整合の1と区別できませんでした。

本人は元のスクリプトを残し、check-run-ids-readable.shへコピーして編集しました。コピーとbash -nの終了コードは0で、差分を提示しました。

引数確認後、awkの前に追加した処理は次のとおりです。

```bash
exec 3< "$1" || {
  echo "検査不能：ログを開けません" >&2
  exit 2
}
```

awkの末尾の入力指定を`< "$1"`から`<&3`へ変更しました。先に入力用のファイル記述子3で開き、成功した場合だけawkへ渡します。掲載内容は案内と差分画像に基づき、ローカル原本の取得・ハッシュ照合は行っていません。

## 本人が確認した修正後の結果

| 入力 | 表示 | 修正版の終了コード |
| --- | --- | --- |
| 存在しないファイル | No such file or directory、検査不能：ログを開けません | 2 |
| START A・END A code=0 | ID=A START=1 END=1 | 0 |
| START Aのみ | ID=A START=1 END=0 | 1 |
| 空ログ | 判定保留：実行IDの記録なし | 3 |

正常サンプルの保存は終了コード0も確認しました。END欠落と空ログの作成は操作画面にあり、作成コマンド単独の終了コードは別途採取していません。

これらは人工サンプルと未作成ファイルの検査です。新しいHTTP接続や実際の同時実行は行っていません。code=0はサンプルに書いた値でありHTTP成功の実績ではありません。

## 理解確認と保存

本人は最初、END欠落とファイルを開けない場合を別の終了コードにする理由が分からないと回答しました。AIの説明後に「ログの記録に問題があるのか、ログを読む前に問題が起きたのかを区別するため」と説明しました。支援なしの独立再実施は未確認です。

本人がid-read-check-2026-09-15.txtを保存し、保存終了コード0とcatによる内容の再表示を提示しました。
