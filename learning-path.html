Learning Pathゼロから学ぶサーバー構築

始める前に8段階障害演習修了判定用語集成果物を見る
所要目安 12〜20時間／自分のPC内の検証環境

読むだけでなく、「予想する → 実行する → 証拠を残す → 説明する」

このページは成果物を見る順番ではなく、未経験者が手を動かす順番です。各段階は、目的・前提・操作・期待結果・失敗例・合格条件を同じ型で確認します。分からない言葉は一言用語集へ戻ります。

安全境界

個人PC内のVMまたはWSL2で実施します。職場・学校・第三者のサーバーでは実行しません。削除・Firewall・SSH変更の前にスナップショットと戻し方を確認します。AWS、Slack実通知、72時間試験、別ホスト復元は手順設計済みですが、このリポジトリでは未実測（NOT RUN）です。

開始チェック

  • CPU、メモリ、ディスク、IPアドレスを自分の言葉で説明できる
  • 端末を開き、現在位置と終了コードを確認できる
  • 8GB以上の空き容量があり、検証環境を削除してよい
  • パスワード、秘密鍵、トークンをGitへ保存しないと理解している
  • 困ったら作業を止め、現象・直前操作・時刻を記録できる

不足があればCUI入門から始める CLI演習案件パックで練習する 詳細ハンズオンを開く

8段階の学習ルート

STEP 0／30分

環境と安全を確認

目的: 壊してよい範囲を決める。

操作: OS、容量、IP、Git状態を採録。

期待: 環境情報ファイルが作られる。

失敗例: 実機とVMの取り違え。

合格: 削除方法と秘密情報の扱いを説明できる。

STEP 1／60分

要件と構成を決める

目的: 作業前に完成条件を決める。

操作: 利用者、通信、RTO/RPO、除外範囲を記入。

期待: 要件と構成図が対応する。

失敗例: 技術名だけで目的がない。

合格: 「誰が何のために使うか」を1分で説明できる。

STEP 2／90分

最小OSを準備

目的: 初期状態を再現する。

操作: Ubuntu VM、一般ユーザー、SSH、更新を準備。

期待: 管理端末から鍵で接続できる。

失敗例: SSH変更後に接続不能。

合格: 再起動後も接続でき、バージョンを記録できる。

STEP 3／2時間

手動で最小構築

目的: 自動化の前に構成を理解する。

操作: Docker、Webサービス、Firewallを設定。

期待: 許可した経路だけ応答する。

失敗例: ポート公開と待受の混同。

合格: 通信経路とログ位置を図で説明できる。

STEP 4／2時間

Ansibleで再構築

目的: 人による手順差を減らす。

操作: syntax-check、check、applyを順に実行。

期待: 2回目は不要な変更が0。

失敗例: 変数未定義、権限不足。

合格: changed=0と差分を証跡に残せる。

STEP 5／2時間

監視と通知を確認

目的: 利用者より先に異常へ気付く。

操作: メトリクス、ログ、ローカル通知を確認。

期待: 発生時刻と復旧時刻が追える。

失敗例: 監視自身の停止を見逃す。

合格: アラートからRunbookへ移動できる。

STEP 6／3時間

障害を切り分ける

目的: 勘ではなく事実で原因を狭める。

操作: 仮説、確認、結果、次の判断を記録。

期待: 復旧前後の証拠が残る。

失敗例: 記録前に再起動する。

合格: 原因と再発防止を第三者へ説明できる。

STEP 7／3時間

復元して引き渡す

目的: バックアップが使えることを確かめる。

操作: 復元、整合性確認、RTO/RPO採録。

期待: 手順だけで再現できる。

失敗例: バックアップ取得だけで終了。

合格: 結果票、残課題、切り戻しを引き渡せる。

正常系の後に行う8つの障害演習

障害、最初の確認、完了条件
障害最初の確認完了条件
SSH接続不可IP → 経路 → TCP/22 → Firewall → sshd遮断箇所を特定し別セッションで復旧
Web応答なしDNS → TCP → Proxy → App → DB依存関係ごとに合否を記録
ディスク逼迫df → inode → du → ログ削除前に原因と保持要件を確認
CPU高騰uptime → top → ps → ログ対象プロセスと発生時刻を特定
メモリ不足free → ps → journal/OOM再起動だけに頼らず原因を記録
設定破損構文検査 → Git差分 → 直前変更修正または切り戻しを選択
TLS期限異常名前解決 → 時刻 → 証明書期限・SAN更新手順と監視閾値を説明
バックアップ破損サイズ → checksum → 展開 → 復元代替世代を選び整合性を確認

  • 監視・切り分け 20点
  • 復旧・記録・引き渡し 20点
