# 案件02追加：バックアップからのファイル復元

実施日：2026年9月14日（JST）

本人がWSL Ubuntuのホーム内で練習用ファイルを変更し、以前保存したバックアップから復元しました。AIが手順を案内し、本人が提示した端末画面を読み取って公開用要約を作成しています。AIの代理実行やCIによる復元結果ではありません。

[9月10日の案件02](./cli-practice-2026-09-10.md)はバックアップ作成・内容一致・権限確認まででした。本書はその後の追加実施です。当時の未実施記録は過去の状態として残します。[同日のnginx停止・復旧演習](./cli-recovery-2026-09-14.md)とは別の、ファイル内容を戻す練習です。

## 対象と操作範囲

- 復元元は案件02で保存したnginxのdefault設定のバックアップです。保存済みファイルと当時の記録の存在を確認しました。
- `mktemp -d`でホーム内に新しい練習用フォルダを作成し、その中のdefaultファイルだけを変更・上書きしました。
- 稼働中のnginx設定には書き込まず、サービスの停止・再読込も行っていません。
- 本文中の`backup_file`はバックアップ、`restore_dir`は今回作成した練習用フォルダを指すシェル変数です。
- 本書のPR作成基点は`cc92400`です。実際のバックアップやOS設定がこのcommitで管理されていたという意味ではありません。

## 本人が実施した操作と結果

| 段階 | 操作 | 提示画面で確認した結果 |
| --- | --- | --- |
| 保存済み記録の確認 | バックアップ一覧と案件02の記録を表示 | 一覧確認・記録確認ともに終了コード0。バックアップは2,412バイト |
| 準備 | mktempで専用フォルダを作成し、cp -pでバックアップを複製 | フォルダ作成0、コピー0 |
| 初期比較 | `diff -u "$backup_file" "$restore_dir/default"` | 差分表示なし、終了コード0 |
| 変更 | 練習用コピー末尾へ空行とコメントを追記 | 変更の終了コード0 |
| 差分検出 | バックアップと変更済みコピーをdiffで比較 | 空行と`# restore practice: changed`の追加を表示、終了コード1 |
| 復元 | `cp -p "$backup_file" "$restore_dir/default"` | 復元の終了コード0 |
| 復元比較 | バックアップと復元済みコピーをdiffで比較 | 差分表示なし、終了コード0 |
| 権限確認 | statで両ファイルの権限を表示 | 両方とも-rw-r--r--、644。stat自体の終了コードは別途採取していない |
| 記録保存 | 本人がWSL内に演習記録を保存してcatで再表示 | 保存の終了コード0と記録内容を確認 |

今回はdiffの結果が「0（一致）→1（差分あり）→0（一致）」と変化しました。変更後の1は比較処理の異常ではなく、意図した差分を検出した結果です。復元時のコピー方向は「バックアップ → 練習用ファイル」であり、バックアップを変更済みの内容で上書きしていません。

cpの成功だけで終えず、復元後の内容一致をdiffで確認し、権限も比較しました。本人は理解確認で、復元方向を「バックアップから練習用ファイル」と説明できました。
