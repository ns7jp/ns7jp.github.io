# 製造業情シス 向け追記

「自動車部品 / 食品 / 化学 / 機械 / 精密」など、**製造業の情報システム部門（本社情シス + 工場系 IT）**を志望する場合の本ポートフォリオの読み方と、口頭補足のポイントです。

製造業情シスは「**OT (Operational Technology) と IT の境界**」「**現場が止まらない安定性**」「**24h 工場稼働の支援**」に特徴があり、SaaS / Web 系の SRE とは別の評価軸を持ちます。

---

## 製造業情シスが重視する 6 つの観点

| # | 観点 | 理由 |
|---|---|---|
| 1 | **OT / IT 分離と接続点の管理** | 製造ネットワーク (PLC / SCADA / MES) と業務ネットワークの分離。Purdue モデル準拠が一般的 |
| 2 | **24h 稼働の安定性** | 工場停止は 1 時間あたり数百万円の機会損失。RTO/RPO の感覚が研ぎ澄まされている |
| 3 | **古い OS / 機器との共存** | Windows Server 2012 や独自 PLC が現役。即リプレースできない |
| 4 | **物理層と現場対応** | サーバールーム + 工場 IT 部屋 + 端末。配線 / UPS / 空調も範囲内 |
| 5 | **ISO27001 / IATF16949 等の監査対応** | 変更管理・アクセスログ・棚卸しの書面エビデンスが評価される |
| 6 | **ベンダー多数 / 多拠点** | 機器ベンダー / SIer / クラウド / 通信キャリアの間に立つ調整役 |

## 製造業特化で追加で言及する点

### 1. OT 領域の「触れない」ことの理解

製造現場の PLC / SCADA / DCS は、IT 側から見ると「動いているのが奇跡」のような古い構成のことが多く、「**ベンダーの保守契約下にあり、勝手にパッチ当てたら保証外**」という制約があります。これを尊重し、

- IT 側のセキュリティ要件は **DMZ 境界の FW / Jump Server** で吸収する
- OT 側のパッチは**ベンダー定期メンテで適用**してもらう
- 直接アクセス権を渡すのではなく、**プロキシ経由のセッション記録**で痕跡を残す

という設計が現実解です。これは本ポートフォリオの **Server VLAN ↔ Guest+IoT VLAN を完全分離 + ACL で必要ポートのみ許可**の考え方と同じです。

### 2. ベンダー / 委託先との橋渡し

製造業情シスは「全部内製」より「**ベンダー数社をうまく動かす**」役割が大半です。本ポートフォリオの

- [チケット分類](../ticket-taxonomy.md) → ベンダーへ依頼するときの**整理済みフォーマット**として使える
- [変更作業ケース](../ad-m365-change-case.md) → ベンダー作業の**事前確認チェックリスト**として使える
- [Postmortem 実例](../postmortem-example.md) → ベンダー報告書の**読み解き方/物足りなさの指摘**ができる

を、内部用ではなく**ベンダーとの共通言語**として運用する想定で説明できます。

### 3. 製造業出身者の現場感

私（島田）は製造・物流現場で 18 年勤務してきました。情シス未経験ですが、

- **現場の人がどこで困っているか**: 端末トラブルが業務停止に直結する感覚
- **シフト制 / 夜勤の運用**: 24h 連絡網と平日昼帯の差
- **改善活動 (KAIZEN)**: 紙の手順書を Excel / 簡易スクリプトで置き換える経験

を肌で持っており、情シスとして配属されてもギャップを感じにくい想定です。

## 入社後 3 ヶ月の進め方 (製造業情シス想定)

| 期間 | 目標 | 具体物 |
|---|---|---|
| 1-2 週目 | サーバールーム + 工場 IT 部屋 + 主要拠点を巡回。物理層と運用台帳の現状を把握 | [物理層棚卸テンプレ](../office-it-physical-layer.md#2-ラック搭載-棚卸テンプレ) を埋める |
| 3-4 週目 | 既存の運用 Runbook / 手順書を読み込み、棚卸しと改訂候補リスト化 | 引き継ぎメモ Markdown、改訂優先度 P1/P2/P3 |
| 2 ヶ月目 | 一次受付 / トリアージを副担当として実施。ベンダー対応の同席で関係性を把握 | チケット 20 件のサマリーを記録 |
| 3 ヶ月目 | 軽微な変更作業 / 定期作業 / 月次レポートを主担当 | 月次レポート 1 本を自分でクローズ |

「**現場が止まらないこと**」が最優先のため、入社直後は破壊的変更は提案せず、**棚卸しと運用見える化**に専念する想定です。

## 補強したい技術 (応募までに / 入社後に)

| 領域 | 状態 | 補強計画 |
|---|---|---|
| **AD / GPO** | Lab レベル (RSAT で休眠ユーザー抽出は実装済) | GPO の継承 / 順序 / フィルタリングの実機検証 |
| **VPN / Zero Trust** | 概念理解 | Tailscale / Cloudflare Access / Zscaler の Lab 構築 |
| **Hyper-V / VMware** | Hyper-V 基本のみ | 検証環境で複数 VM 構築 / Live Migration 検証 |
| **Windows Server 系** | Lab レベル | DFS / Print Server / IIS / NPS の運用観点 |
| **資格** | ITパスポート (取得予定 2026-06) | LPIC-1 → CCNA → AZ-104 |
