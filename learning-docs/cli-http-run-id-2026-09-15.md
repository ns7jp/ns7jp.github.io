# HTTP実行ログへの実行ID追加

実施日：2026年9月15日（JST）

本人がWSL Ubuntuでrun-http-check-id.shを作成し、正常ページとHTTP 404の実行ログに共通の実行IDを持つSTART・ENDを記録しました。AIが手順を案内し、本人が提示した端末画像を読み取って公開用要約を作成しています。AIの代理実行やCIの実測ではありません。

[人工サンプルでの実行ID](./cli-log-run-id-2026-09-15.md)を、[確認条件・終了日時を記録する実行用スクリプト](./cli-http-trace-2026-09-14.md)へ組み込んだ追加演習です。

## 追加した処理

元のスクリプトを残して別名の修正版へコピーする手順で進めました。検索・作業先作成は終了コード0、構文検査は0、差分は次の3行追加で終了コード1でした。コピー自体の終了コードは提示画像では未確認です。

ログを開く前に実行IDを生成します。

```bash
run_id=$(cat /proc/sys/kernel/random/uuid) || exit 125
```

開始日時を書いた直後に、同じ変数を使ってSTARTを記録します。

```bash
printf 'START run_id=%s\n' "$run_id" >&3 || exit 125
```

確認処理の終了コードを記録した後、ログ出力先を閉じる前にENDを追加します。

```bash
printf 'END run_id=%s code=%s\n' "$run_id" "$check_status" >&3 || exit 125
```

掲載コードは案内と差分画像に基づきます。ローカル原本を取得・ハッシュ照合したものではありません。

## 本人が実施した結果

既存のcheck-http-body.shを呼び出す修正版をbash経由で2回、順番に実行しました。

| 試験 | HTTPと本文 | START・END | 実行用スクリプト終了コード |
| --- | --- | --- | --- |
| 正常URL・既定の期待文字列 | HTTP 200、Welcome to nginx!を含む本文の行、成功 | 同じID、ENDのcode=0 | 0 |
| 存在しないURL | HTTP 404、curlエラー、HTTP取得失敗 | 同じID、ENDのcode=22 | 22 |

2回のIDは異なっていました。正常時はログ全体をcat、404時は末尾13行をtailで表示し、両表示の終了コードは0でした。404時の表示には前回のENDも含まれており、今回のIDとの違いを比較できました。

実際のIDは公開しません。関係だけを模式的に表すと、正常時はSTART A・END A code=0、404時はSTART B・END B code=22です。A・Bは公開説明用の置き換えで、スクリプトが生成した文字列そのものではありません。

## 対応付けの範囲

今回は各実行の開始と結果が同じIDで、2実行間では異なることを目視確認しました。IDの一意性を網羅的に保証したわけではなく、重複・欠落の自動検査も実装していません。

全ログ行にIDを付けたわけではなく、今回の追加対象はSTARTとENDです。同時実行で中間出力が混ざった場合の識別や、複数行の原子的な書き込みを保証する変更ではありません。また、準備失敗でSTART前に止まる場合や途中でENDが欠ける場合の検証は未実施です。

## 理解確認と保存

本人は最初、同じ実行には同じID、別の実行には別IDを使う目的が分からないと回答しました。AIの説明後、「同じ実行の開始と結果を結び付け、別の実行と混ざらないようにするため」と説明しました。支援なしの独立再実施は未確認です。
