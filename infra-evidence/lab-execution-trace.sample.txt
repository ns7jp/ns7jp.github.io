8) アラート発火確認 (HostHighMemory を意図的に再現する場合)
===============================================================================

# 負荷ツールでメモリ消費を上げ、しきい値 (used > 90%) を超えさせる
$ docker run -d --rm --name mem-burner --memory=2g -p 8085:8085 \
    polinux/stress stress --vm 2 --vm-bytes 1.7G --vm-keep --timeout 1200

# 15 分後、アラートが firing 状態へ
$ curl -s http://localhost:9090/api/v1/alerts | jq '.data.alerts[] | select(.state == "firing") | {name: .labels.alertname, severity: .labels.severity, since: .activeAt, value: .value}'
{
  "name": "HostHighMemory",
  "severity": "warning",
  "since": "2026-05-25T07:24:33.018Z",
  "value": "91.4"
}

所要時間まとめ
===============================================================================

- git clone: 約 6 秒
- docker compose up -d (初回 pull 含めず): 約 5 秒
- 全サービスが Ready 状態になるまで: 起動から約 30 秒
- ダッシュボード初回表示: Grafana のサインインから 2 クリックで両方表示
- アラート発火確認 (意図的な負荷生成から): for 15m なので約 15 分待機

合計: 初回構築から動作確認まで実機で 10 分以内 / 再構築は 1 分以内。
