# ログ読み取りエラーの確認

実施日：2026年9月14日（JST）

本人がWSL Ubuntuで作成していないファイルをgrepに指定し、読み取りエラーを確認しました。AIが手順を案内し、本人が提示した端末画像を読み取って公開用要約を作成しています。AIの代理実行やCIの実測ではありません。

[失敗0件と空ログの比較](./cli-log-count-empty-2026-09-14.md)に続く演習です。今回は意図的なファイル不在の試験で、新しいHTTP接続やnginxの操作は行っていません。

## 本人が実施した操作と結果

| 段階 | 操作 | 提示画面で確認した結果 |
| --- | --- | --- |
| 準備 | mktemp -dで新しい検証用フォルダを作成 | 終了コード0 |
| 読み取り | 作成していないnot-created.logにgrep -cEを実行 | No such file or directory、grep終了コード2 |
| 判断 | 件数を報告できるか確認 | ファイルを読めず集計不能。失敗件数は不明 |
| 保存 | 本人が演習要約を保存し、catで再表示 | 保存終了コード0と記録内容を確認 |

実行した検索の形は次のとおりです。read_test_dirは直前に作成した検証用フォルダで、その中にnot-created.logは作成していません。

```bash
grep -cE '^スクリプト終了コード=[1-9][0-9]*$' "$read_test_dir/not-created.log"
echo "検索の終了コード=$?"
```

既存ログを削除してエラーを起こしたのではありません。今回の意図した読み取り失敗を、実サービスの障害や既存ログの消失とは扱いません。

## 一致なしと集計不能の違い

[以前の件数集計](./cli-http-log-count-2026-09-14.md)と空ログ比較を含め、実際に確認したgrepの結果を区別しました。

| 終了コード | 確認した状況 |
| --- | --- |
| 0 | 以前の試験で、条件に一致する行が見つかった |
| 1 | 以前の人工サンプルで、一致する行がなかった |
| 2 | 今回、対象ファイルが存在せず読み取れなかった |

0・1の行は過去の結果で、今回再実行したものではありません。今回の2はファイル不在によるエラーであり、すべての終了コード2の原因がファイル不在だと一般化しません。

ファイルを読めていないため、失敗件数を0とは報告できません。「集計不能・件数不明」として、実際に集計して0件だった状態と区別しました。
