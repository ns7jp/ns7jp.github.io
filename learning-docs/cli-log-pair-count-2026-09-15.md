# 開始・終了の件数一致と対応関係の違い

実施日：2026年9月15日（JST）

本人がWSL Ubuntuで人工サンプルを作成し、開始と終了の件数が一致しても、各実行の対応関係は確定できないことを確認しました。AIが手順を案内し、本人が提示した端末画像を読み取って公開用要約を作成しています。AIの代理実行やCIの実測ではありません。

[開始記録と終了記録の件数比較](./cli-log-completion-2026-09-15.md)に続く演習です。今回は実際のHTTP実行ログではなく、集計の限界を調べる人工入力です。

## 入力と本人の操作

新しい検証用フォルダに、次の内容のoverlap.logを作成しました。

```text
開始日時=sample-A
開始日時=sample-B
スクリプト終了コード=0
スクリプト終了コード=0
```

sample-A・sample-Bは説明用のラベルで、実日時ではありません。本人がprintfで4行を書き、cat -nで順序を確認しました。フォルダ作成・保存・表示は終了コード0でした。

次の条件で件数を比較しました。sample_fileは今回の人工サンプルを指す説明用の変数です。

```bash
grep -c '^開始日時=' "$sample_file"
grep -cE '^スクリプト終了コード=[0-9]+$' "$sample_file"
```

| 検索 | 表示された件数 | grep終了コード |
| --- | --- | --- |
| 開始日時で始まる行 | 2 | 0 |
| 数値のスクリプト終了コード行 | 2 | 0 |

## 読み取れることと限界

開始が2行続いた後、結果0が2行並んでいます。件数は一致しますが、結果の行にA・Bの識別情報がないため、どの開始にどの結果が対応するか、このサンプルだけでは確定できません。

この結果は記録の不正や実行失敗を証明するものではありません。各開始に結果が1つずつある可能性もありますが、件数一致だけではそれを検証できないという限界を確認しました。実際の同時実行や通信は行っていません。

## 理解確認と保存

「開始と終了が同じ件数なら、すべての実行結果が正しく記録されたと判断してよいか」という質問に、本人は「ダメです」と回答しました。AIは各開始と結果の対応が未確認であることを補足しました。支援なしの独立再実施は未確認です。

本人がlog-pair-count-2026-09-15.txtをWSL内に保存し、保存終了コード0とcatによる記録内容の再表示を提示しました。

- 根拠は本人提示画像です。人工入力を作成して検索した操作は本人実施ですが、HTTP成功2回の実績ではありません。
- **NOT RUN**：実行IDによる対応付け、対応関係の自動検査、実際の同時実行試験、定期実行。
- 既存の実行ログやスクリプトは変更せず、検証用フォルダ・人工サンプル・演習記録を作成しました。
- 個人環境のIP・ホスト名・ユーザー名・絶対パス、鍵情報、画像、ローカル原本、完全な生ログは公開しません。
- 第三者の独立再検証や原本のハッシュ照合は未実施です。静的チェックやCIは公開文書の検証であり、本人環境での操作の再実行ではありません。
