設計判断とトレードオフ

ADR-01

まずUbuntu 1台に範囲を固定

設計から引き渡しまでを一周することを優先し、複数ホスト・HAは初期範囲から外しました。D-2や外部probeは次段階として明示します。

ADR-02

Ansibleを役割単位に分離

common / docker / nginx / monitoringへ分け、変更箇所と検証範囲を限定しました。Moleculeで4ロールの冪等性を確認しています。

ADR-03

管理画面はloopback公開を原則化

Grafana等を外部へ直接公開しない方針です。2026年8月22日に使い捨てrunner内のlistenとUFWを確認しましたが、独立した管理端末・引き渡し対象ホスト・組織DNSからの到達性は未実測です。

ADR-04

メトリクスとログを同じ画面へ

PrometheusとLokiをGrafanaへ集約し、数値の変化と同時刻のログを行き来できる構成にしました。WSL2上で実データ表示を確認しています。

ADR-05

未実測を空欄にしない

未実施項目はNOT RUNと理由を残します。使い捨てrunnerの成功を独立した引き渡し対象ホストの構築成功へ読み替えず、次に必要な検証が分かる台帳にしています。

結果・学び・次の一手

実測できたこと

  • Docker導入済みのdisposable Ubuntu 24.04 runnerへsite.ymlを2回適用し、2回目changed=0を確認。
  • 2026-08-22 E2Eでcore 10 servicesとCI webhook sinkの計11 containersを起動し、local webhookのFIRING / RESOLVEDを確認（Slack実配信ではありません）。
  • Docker API proxyのGET成功・POST拒否と、proxyが取得した固有Nginx logのAlloy経由Loki到達を確認。GETの読取権限は残るため、完全なleast privilegeではありません。
  • runner内のnetwork / UFWを検証し、D-1を1秒で復旧。
  • Prometheus・Grafana・Lokiの3 volumeをbackup / restoreし、Full-stack E2E 23 / 23 IDをPASS。
  • 履歴：2026年8月19日は全体11 / 21 PASS、D-1 RTO 13秒。最新値とは分けて保存。

まだ実測していないこと

  • 構成commit／設定を前版へ戻すrollback rehearsal。
  • AlertmanagerからSlackへの実配信。
  • AWS apply / destroyとD-2ホスト障害。
  • 独立した管理端末と引き渡し対象ホストでの構築・疎通・運用。
  • 組織DNSを使った名前解決と長期稼働。
面接で説明できる改善事例

D-1演習では2回失敗し、障害注入方法と古いローカルブランチを原因として切り分けました。成功結果だけでなく、誤った前提、確認コマンド、修正、再試験まで記録しています。
