# curlの終了コードによる条件分岐

実施日：2026年9月14日（JST）

本人がWSL Ubuntuの端末で、curlをifの条件に使い、正常ページと存在しないページで処理が分かれることを確認しました。AIが手順を案内し、本人が提示した端末画像を読み取って公開用要約を作成しています。AIの代理実行やCIによる実測ではありません。

[--fail-with-bodyの比較演習](./cli-curl-fail-with-body-2026-09-14.md)に続く追加実施です。前回未実施だった条件分岐を端末上で実行しました。過去の記録は当時の状態として残し、実行用スクリプトファイルを作成したとは扱いません。

## 本人が実施した操作と結果

対象は同じWSL内の練習用nginxです。curlにはプロキシを使わない指定、最大10秒の制限、--fail-with-body、-sS、HTTPステータスの表示を指定しました。本文は-o /dev/nullで破棄しています。

| 対象 | HTTPステータス | curlの終了コード | 端末で確認した分岐 |
| --- | --- | --- | --- |
| 正常な初期ページのURL | 200 | 0（then側への分岐で確認） | 成功側のメッセージを表示 |
| 目印を含む存在しないページのURL | 404 | 22（変数へ保存して表示） | 失敗側のメッセージを表示 |

404時にはcurlのエラーメッセージも表示されました。これは想定した失敗側への分岐であり、演習そのものの失敗ではありません。

実行した条件分岐の要点は次のとおりです。以下は構造を説明する抜粋で、curlの引数を省略しているため、そのまま実行するコマンドではありません。

```text
if curl ...
then
  成功側のメッセージを表示
else
  curl_status=$?
  保存した終了コードを含む失敗側のメッセージを表示
fi
```

elseの直後にcurl_status=$?を実行し、他のコマンドで上書きされる前にcurlの終了コードを保存しました。今回のifが直接評価するのはHTTPステータスの数値や表示文字列ではなく、curlの終了コードです。

両分岐の最後はechoで表示しています。if全体や後続のechoの終了コードを、curl自身の終了コードと混同しません。この処理をそのまま監視用スクリプトの終了コード設計として検証したわけではありません。
