# 失敗0件と空ログの区別

実施日：2026年9月14日（JST）

本人がWSL Ubuntuで人工サンプルを2種類作成し、失敗件数だけでは記録の有無を区別できないことを確認しました。AIが手順を案内し、本人が提示した端末画像を読み取って公開用要約を作成しています。AIの代理実行やCIの実測ではありません。

[前回の件数集計](./cli-http-log-count-2026-09-14.md)で未実施だった失敗0件・空ログの追加試験です。今回の入力は人工サンプルであり、HTTPを実行したログやサービス稼働の証拠ではありません。

## サンプルと操作

新しい検証用フォルダに次の2ファイルを作りました。フォルダ作成・サンプル保存・空ファイル作成は終了コード0でした。

- success-only.log：スクリプト終了コード=0という行を2行、printfで作成。
- empty.log：内容のないファイルを作成。

まず失敗行を数え、次に全記録行を数えました。次は検索条件を示す抜粋です。対象ファイルはそれぞれのサンプルを指定しました。

```bash
grep -cE '^スクリプト終了コード=[1-9][0-9]*$' "$sample_file"
grep -cE '^スクリプト終了コード=[0-9]+$' "$sample_file"
```

## 本人が確認した結果

| 人工サンプル | 失敗件数 | 失敗検索の終了コード | 全記録数 | 全件検索の終了コード |
| --- | --- | --- | --- | --- |
| 正常のみの2行 | 0 | 1 | 2 | 0 |
| 空ログ | 0 | 1 | 0 | 1 |

grep -cの件数表示と、grep自身の終了コードを区別しました。ここでの終了コード1は一致する行がなかったことを示し、読み取りエラーを観測したという意味ではありません。

失敗検索だけでは両方とも0件・終了コード1で同じ結果になります。今回のサンプルでは全記録数を併せて確認することで、正常を表す2行がある状態と、記録自体がない状態を区別できました。

ただし、全記録数は正規表現に一致した行数です。任意のファイルで全記録数0を空ファイルと断定できるわけではなく、形式不正で一致しない場合などの検証は未実施です。

## 理解確認と保存

「失敗件数が0でも全記録数が0なら正常に動いていると判断してよいか」という質問に、本人は「ダメです」と回答しました。記録がない状態を正常の根拠にしないことを確認しました。支援なしの独立再実施は未確認です。

本人がWSL内にlog-count-empty-2026-09-14.txtを保存し、保存終了コード0とcatによる記録内容の再表示を提示しました。
