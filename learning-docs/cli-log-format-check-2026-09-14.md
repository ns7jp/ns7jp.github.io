# ログ集計前の形式検査

実施日：2026年9月14日（JST）

本人がWSL Ubuntuで人工サンプルを使い、既存の集計スクリプトが不正行を無視する問題を再現しました。別名の修正版へ形式検査を追加し、5通りの判定を確認しました。AIが手順を案内し、本人が提示した端末画像を読み取って公開用要約を作成しています。AIの代理実行やCIの実測ではありません。

[集計スクリプト](./cli-log-summary-script-2026-09-14.md)と[実際の履歴への適用](./cli-log-summary-history-2026-09-14.md)に続く追加演習です。今回の入力は人工サンプルで、HTTP実行や本番ログの調査実績ではありません。

## 修正前に再現した問題

新しい検証用フォルダ内に、次の2行を持つmalformed.logを作成しました。スクリプト検索・フォルダ作成・サンプル保存は終了コード0でした。

```text
スクリプト終了コード=0
スクリプト終了コード=ERROR
```

修正前のsummarize-log.shは数値の行だけを数え、全1件・失敗0件、失敗記録なし、終了コード0を返しました。ERRORの行が集計から抜けても、呼び出し元へ不備を知らせられないことを確認しました。

## 追加した形式検査

元のスクリプトを残すため、summarize-log-checked.shへコピーして編集する手順を案内しました。コピー自体の終了コードは提示画像では未確認です。修正版のbash -nは終了コード0で、その後の動作も確認しました。

次の処理をlog_fileへの引数代入後、件数集計前に追加するよう案内しました。掲載コードは案内内容であり、本人のローカル原本を取得・ハッシュ照合したものではありません。

```bash
awk '
  /^スクリプト終了コード=/ {
    if ($0 !~ /^スクリプト終了コード=(0|[1-9][0-9]*)$/) {
      print "不正な記録：行" NR
      invalid=1
    }
  }
  END { if (invalid) exit 4 }
' "$log_file"
format_status=$?

if [ "$format_status" -eq 4 ]; then
  echo "集計中止：終了コードの形式が不正です" >&2
  exit 4
elif [ "$format_status" -ne 0 ]; then
  echo "集計不能：形式検査でエラー" >&2
  exit 2
fi
```

検査対象はスクリプト終了コード=で始まる行です。0、または先頭が1〜9の数字列という形式を要求します。見出し・日時などの行は検査対象ではありません。

## 本人が確認した修正後の結果

| 人工入力 | 表示・判定 | 修正版の終了コード |
| --- | --- | --- |
| =0と=ERROR | 2行目が不正、集計中止 | 4 |
| =0と=22 | 全2件・失敗1件、失敗記録あり | 1 |
| =0の1行 | 全1件・失敗0件、失敗記録なし | 0 |
| 空ログ | 判定保留：集計対象の記録がありません | 3 |
| 存在しないファイル | awkのファイル読取エラー、集計不能：形式検査でエラー | 2 |

修正前は見落とした不正行を、修正後は行番号付きで知らせ、成功扱いせず中止できました。既存の正常・失敗あり・空ログ・読み取りエラーの判定も今回のサンプルで確認しました。
