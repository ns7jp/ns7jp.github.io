## 変更を安全に進める型

設定を変えるときは、自動テストで不具合を先に見つけ、問題が出たときに前の状態へ戻せるようにします。

### 失敗を見つけ、原因を調べて修正

**状態：GitHubの自動テストで実測済み**

GitHub上の自動テスト（決めた確認項目を機械が自動で実行する仕組み）で2つの問題を検出しました。修正後、23項目すべてが合格することを確認しました。同じ手順を2回目に実行しても不要な変更が出ないこと（冪等性／同じ操作を何度実行しても結果が変わらない性質）も確認しました。

[PR #75を確認](https://github.com/ns7jp/server/pull/75)

### 指定した前の版へ戻す

**状態：自動テストで確認済み**

自動テストでは、新しい版を確認したあと、指定した前の版へ正確に戻しました。この作業は切り戻し（問題が出たときに以前の状態へ戻すこと）と呼ばれます。戻したあと、アプリとログが正しく動くことを確認しました。

[切り戻しの記録を確認](https://github.com/ns7jp/server/actions/runs/32611251044)

### 本番変更は単独判断しない

**方針：実務では要レビュー**

目的、影響範囲、事前確認、実施手順、切り戻し条件、事後確認を、他の人が読んで確認できる形にまとめます。そのうえで、承認と自分の担当範囲を確認してから進めます。

## AIを使った範囲と、自分で確認したこと

このサイトと関連作品では、文章整理だけでなくプログラム作成にもAIを使いました。AIが出した内容を、そのまま自分の実績とは呼びません。公開している記録には、実施者、環境、AI支援の有無を書いています。AIを使わずに再現した記録はまだなく、自分の言葉で説明できるよう練習を続けています。

### AIを使うときに自分で行うこと

- 目的、対象範囲、完了条件を決める
- なぜその方法を選んだか説明する練習をする
- どの環境とコードの版で試したか記録する
- 結果を確認し、未実施を明記する

### AIに依頼する範囲

- コード・テスト・文書の案出し
- エラー原因の候補を出す
- 確認項目の漏れを探す
- 繰り返し作業と文章の整理

### 面談に向けて説明・実演を練習すること

- 主要構成を図と言葉で説明する練習
- 保存した記録から判断理由を説明する練習
- 実演は、本人の環境で通して実行した演習に限る
- 分からない点を分からないと回答する

[AI利用の詳細](https://github.com/ns7jp/ns7jp/blob/main/README.md#3-つの前提ai-の利用を含む) / [実行時に見つけた欠陥と修正](https://ns7jp.github.io/evidence-demo.html)

## 次に確認したいこと：仮想マシンでの通し確認と長時間稼働

**以下は、確認済みの部分結果を踏まえた未完了の確認計画です。**

2026年9月7日〜8日に、手元のHyper-V上の仮想マシンへUbuntu Server 24.04を手作業で初期構築しました（固定IP、SSH鍵認証、UFW、時刻同期、自動更新。[初期構築の記録](https://github.com/ns7jp/server/blob/main/docs/evidence/2026-09-08-lab-base01-initial-build.md)）。監視と復元は、その仮想マシンで構成を切り替えた別々の練習です。以下を終えるまで、「独立したサーバーを構築・運用した実績」とは表現しません。

### 1. 監視をまとめて動かす

11月5日には、AIの案内を受けた本人操作で、KVM上の7サービス部分構成の監視・ローカル通知・手動復旧・復旧通知を確認しました。[本人実習の記録](https://github.com/ns7jp/server/blob/main/docs/evidence/2026-11-05-kvm-monitoring-notification.md)。原画像・生ログ・受信JSONはリポジトリ未収録で、ファイル内容の独立照合も未実施です。

この部分構成での結果を、Grafana・Loki等を含む全構成の通し検証とは分けます。次は全構成で停止・復旧を確認し、通知がSlack等の外部へ届くことを確かめます。独力再現・長期稼働も引き続き未確認です。

### 2. AlmaLinuxの新規構築

新しい仮想マシンにAlmaLinux（RHEL系のLinux）を入れ、必要な通信だけを公開する構成を作ります。設定を変える前の最初の状態も記録し、あとで何をどう変えたかを比べられるようにします。

### 3. 再起動・前の版への切り戻し・復元

ホスト再起動後の動作、指定した前の版への戻し、別の新しい仮想マシンへの復元、監視とログの再開を確認します。

### 4. 長時間動作と引き継ぎ確認

24時間・72時間の連続動作を試します。そのうえで、分かっている制約、復旧条件、引き継ぎチェックリストを、実際の結果に合わせて更新します。AIの案内なしでの再構築と、第三者による手順の確認も残っています。
