# 実行IDで開始と終了を対応付ける

実施日：2026年9月15日（JST）

本人がWSL Ubuntuで人工サンプルを作成し、開始と終了に共通の実行IDを付けて、終了順が入れ替わった記録を対応付けました。AIが手順を案内し、本人が提示した端末画像を読み取って公開用要約を作成しています。AIの代理実行やCIの実測ではありません。

[開始・終了の件数一致と対応関係](./cli-log-pair-count-2026-09-15.md)に続く演習です。今回の入力は人工サンプルで、実際のHTTP接続や同時実行は行っていません。

## 入力と本人が確認した結果

新しい検証用フォルダにidentified.logを作成しました。

```text
START run_id=A
START run_id=B
END run_id=B code=22
END run_id=A code=0
```

フォルダ作成・保存・cat -nによる表示は終了コード0でした。次の検索で各IDの行を取り出しました。sample_fileは確認した人工サンプルを指す説明用の変数です。

```bash
grep -nE ' run_id=A( |$)' "$sample_file"
grep -nE ' run_id=B( |$)' "$sample_file"
```

| ID | 抽出した開始 | 抽出した終了 | 検索終了コード |
| --- | --- | --- | --- |
| A | 1行目 START run_id=A | 4行目 END run_id=A code=0 | 0 |
| B | 2行目 START run_id=B | 3行目 END run_id=B code=22 | 0 |

検索パターンはIDの後ろに空白または行末を要求しています。AとAAのような別IDの混同を避ける意図の指定ですが、AAを含むサンプルでの試験は未実施です。

## 対応付けの読み取り

Bの終了がAより先に現れても、同じrun_idによってAの開始と結果0、Bの開始と結果22を結び付けられました。grepの終了コード0は検索成功であり、サンプルのcode=22が成功だったという意味ではありません。

code=0・22は人工入力として書き込んだ値です。HTTP成功・失敗をその場で実行して得た結果ではなく、並んだ記録を検索して読む練習です。実行IDを付けただけで、IDの一意性や欠落・重複が自動的に保証されるものではありません。

## 理解確認と保存

本人は最初、開始と終了に同じIDを付ける目的が分からないと回答しました。AIの説明後、「どの開始に、どの終了結果が対応するか分かるようにするため」と説明しました。支援なしの独立再実施は未確認です。

本人がWSL内にlog-run-id-2026-09-15.txtを保存し、保存終了コード0とcatによる内容の再表示を提示しました。
