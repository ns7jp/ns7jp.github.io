# HTTP実行ログに確認条件と終了日時を追加

実施日：2026年9月14日（JST）

本人がWSL Ubuntuでrun-http-check-trace.shを作成し、実行ログに対象URL・期待文字列・終了日時を追加しました。AIが手順を案内し、本人が提示した端末画像を読み取って公開用要約を作成しています。AIの代理実行やCIによる実測ではありません。

[HTTP確認とログ保存の実行用スクリプト](./cli-http-runner-2026-09-14.md)から別名の修正版を作る手順で進めました。以前のログでは対象URLと期待文字列を記録しておらず、結果を調べる際に操作画面との照合が必要でした。

## 追加した内容

開始日時の記録直後に、次の行を追加しました。

```bash
printf '対象URL=%s\n期待文字列=%s\n' "$url" "$expected" >&3 || exit 125
```

確認処理直後のcheck_status=$?を残し、その後に次を追加しました。

```bash
finished_at=$(date -Is) || exit 125
printf '終了日時=%s\n' "$finished_at" >&3 || exit 125
```

コードは案内内容と提示画面に基づき、ローカル原本の取得・ハッシュ照合は行っていません。検索・作業先作成は終了コード0でした。修正版作成時のコピー終了コードは提示画像では未確認です。

## 初回の失敗と修正

追加3行の差分とbash -nの終了コード0を確認して実行しましたが、HTTP 200・本文一致の後でdateの不正オプションエラーが発生しました。実行用スクリプトは125を返し、history.logには開始日時・対象・期待値・HTTP結果は残った一方、終了日時とスクリプト終了コードは残っていませんでした。

エラー表示はdate: invalid option -- 'l'でした。終了日時取得のオプションを大文字Iの-Isに修正する手順を案内し、本人は修正後のfinished_at行とbash -nの終了コード0を提示しました。修正前の実ファイルを取得して文字単位で検査したものではありません。

この事例では、シェルの構文検査が通っても、内部コマンドのオプション誤りまでは検出できませんでした。また125はHTTP取得失敗ではなく、HTTP確認後の日時取得失敗でした。

## 修正後の本人実施結果

未完了のhistory.logを消さず、別のverified.logへ保存する手順で再試験しました。

| 試験 | ログに残った情報 | 実行用スクリプト終了コード |
| --- | --- | --- |
| 正常URL・既定の期待文字列 | 開始日時、対象URL、Welcome to nginx!という期待文字列、HTTP 200、一致した本文の行、終了日時、結果0 | 0 |
| 同じURL・本文にない期待文字列 | 前回記録を残して追記。対象URL、変更した期待文字列、HTTP 200、本文確認失敗、開始・終了日時、結果1 | 1 |
| 存在しないURL | 目印付き対象URL、期待文字列、curlエラー、HTTP 404、開始・終了日時、結果22を末尾で確認 | 22 |

各ログ表示の終了コードは0でした。正常時と本文不一致時は全体をcatで確認し、404時は末尾12行をtailで確認しました。本文検査は文字列の包含で、ページ全体の完全一致ではありません。

開始・終了日時は秒単位の壁時計時刻です。高速な処理で同じ秒が表示されても、処理時間が厳密に0だったとは扱いません。単調時計による所要時間計測は未実施です。
