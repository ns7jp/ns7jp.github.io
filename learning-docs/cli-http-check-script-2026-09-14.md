## 本人が作成した処理

新しい練習用フォルダに、次の内容を保存しました。コードは会話で案内し、提示画面で保存操作を確認した内容です。個人環境のローカル原本を取得・ハッシュ照合したものではありません。

```bash
#!/usr/bin/env bash

url="${1:-http://127.0.0.1/}"

if curl --noproxy '*' --max-time 10 --fail-with-body -sS \
  -o /dev/null -w 'HTTPステータス=%{http_code}\n' "$url"
then
  echo "成功側：curlの終了コードは0"
  exit 0
else
  curl_status=$?
  echo "失敗側：curlの終了コード=$curl_status"
  exit "$curl_status"
fi
```

URLは第1引数で受け取り、引数が未指定または空ならループバックの既定URLを使います。本人が試したのは引数省略時の正常ページと、明示的にURLを渡した404です。空の引数を渡す試験は未実施です。

これは学習用の最小スクリプトで、HTTP 200だけを許可する判定や、期待する本文の検査は含みません。curlが成功とする他の応答を、ページ内容まで正常と保証するものではありません。

## 終了コードを返す理由

失敗側ではelse直後にcurl_status=$?でcurlの結果を保存し、echoの後にexitでその値を返します。これにより、メッセージを表示するだけでなく呼び出し元へ失敗を伝えられます。今回の404では実際に22が返りました。

本人は最初の理解確認では分からないと回答しました。AIの説明後、「保存したcurlの終了コード22を、スクリプト自身の終了コードとして返すため」と説明しました。案内後の理解確認であり、支援なしの独立再実施は未確認です。
