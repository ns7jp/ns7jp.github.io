暗記より先に「何を確かめたいか」を覚える

コマンドは、画面を開かずにコンピューターへ質問する短い文章です。このページでは、問い合わせや障害の一次確認で使うコマンドを、端末 → 場所 → 通信 → 動作 → 記録 → 権限の6分類で学びます。最初はすべて覚えず、「どの分類を調べればよいか」を選べれば十分です。

合言葉：端・場・通・動・記・権たん・ば・つう・どう・き・けん

端末情報 → ファイルの場所 → 通信 → プロセスやサービスの動作 → イベント記録 → ユーザーと権限、の順です。以降の見出し横にある小さなラベルは、その節がどの文字に対応するかを示します。

検証範囲：学習用（実機での全コマンド一括検証は未実施）

掲載内容はWindowsの一次確認を学ぶための例です。このページの全コマンドを同一のWindows Server実機で実行した証跡ではありません。環境により表示名や使用できるコマンドが異なります。業務環境では会社の手順、権限、対象サーバー、変更の有無を確認してください。

CMDとPowerShellは何が違う？

CMD

コマンド プロンプト

昔からあるWindowsの操作画面です。ipconfig、ping、dirなど、短い基本コマンドを覚える入口に向いています。

Win + R → cmd → Enter
ipconfig /all
PowerShell

PowerShell

結果を文字列だけでなく「情報のまとまり」として扱えます。Get-は取得、Test-は確認、Set-は変更、と動詞から目的を推測できます。

Win + X → ターミナル
Get-ComputerInfo
プロンプト記号は入力しません

説明にあるC:\>やPS C:\>は「入力を待っています」という表示です。入力するのは、その右側のコマンドだけです。管理者権限が必要な場合も、まず通常権限で確認し、理由が分かってから「管理者として実行」します。

通信障害は「自分 → 名前 → 道 → 入口」で分ける

通
1

自分の設定：ipconfig /all

IPv4アドレスは自分の住所、サブネットマスクは同じ地域の範囲、既定ゲートウェイは別ネットワークへの出口、DNSは名前を住所へ変換する案内所です。169.254.x.xは、DHCPからアドレスを取得できなかった可能性があります。

2

名前：nslookup server01

サーバー名が期待するIPへ変換されるかを見ます。名前では失敗し、IP直接なら成功する場合はDNSを調べます。

3

道：tracert server01

通信が通る機器を順番に表示します。途中の*は応答を返さない設定の場合もあるため、そこで障害と即断しません。

4

入口：Test-NetConnection server01 -Port 443

WebのHTTPS入口であるTCP 443番へ接続できるか確認します。PCからの到達、ファイアウォール、待受サービスを切り分ける材料になります。

ping失敗 ＝ サーバー停止、ではありません

セキュリティ設定でpingだけを拒否していることがあります。名前解決、対象ポート、別PCからの結果も集めて判断します。

プロセス・サービス・ログをつなげて読む

動記

プロセスは「今動くプログラム」

Get-Process |
  Sort-Object CPU -Descending |
  Select-Object -First 10

|（パイプ）は左の結果を右へ渡します。CPU使用時間の大きい順に10件表示しますが、値が大きいだけで異常とは限りません。普段の状態、発生時刻、継続時間と比べます。

サービスは「裏側で動く機能」

Get-Service -Name W32Time
Get-Service | Where-Object Status -eq 'Stopped'

W32Timeは時刻同期サービスです。停止中一覧には、必要なときだけ起動する正常なサービスも含まれます。設計や通常時の状態を確認してから判断します。

イベントログは「何が起きたかの記録」

Get-WinEvent -FilterHashtable @{
  LogName='System'; Level=2
} -MaxEvents 20

Level=2はエラーです。時刻、ProviderName（記録元）、Id、Messageを控えます。同じIDでも原因が同じとは限らないため、メッセージと前後の操作を合わせて読みます。

結果をファイルへ保存

Get-ComputerInfo |
  Out-File "$env:USERPROFILE\Desktop\computer-info.txt"

Out-Fileは結果を保存します。既存ファイルを同名で上書きする点と、端末名・更新情報などが外部へ出ないよう保存先と共有先に注意します。

止まって確認する変更コマンド

次のコマンドは便利ですが、サービス停止、データ消失、通信断を起こす可能性があります。対象、影響、承認、バックアップ、戻し方、確認方法がそろうまで業務環境では実行しません。

del / Remove-Item削除対象パスと復元方法を確認
format / diskpartディスク変更対象を誤るとデータ消失
Stop-Service / sc stopサービス停止利用者と依存機能へ影響
Restart-Computer / shutdown再起動・停止接続中の利用者と処理を確認
netsh / Set-NetFirewallRule通信設定変更遠隔接続を失う可能性
net user /addアカウント変更申請と最小権限を確認
PowerShellの安全機能

対応コマンドでは-WhatIfで実行予定だけを表示し、-Confirmで確認を求められます。ただし全コマンドが対応するわけではありません。テスト環境、対象を限定した小さな操作、実行後の再確認を組み合わせます。

10分でできる3つの練習

自分の学習用PCで、設定を変更しない確認だけを行います。結果に個人情報が含まれるため、そのままSNSや公開リポジトリへ載せないでください。

練習 1

対象確認メモを作る

  1. hostnameとwhoamiを実行。
  2. Get-Dateで確認時刻を表示。
  3. 「いつ・誰が・どの端末で」を自分の言葉で説明。
できたか確認

3情報を説明でき、端末名やユーザー名を公開してよい情報か判断できれば完了です。

練習 2

Web接続を4段階で確認

  1. ipconfig /allで自分の設定。
  2. nslookup example.comで名前解決。
  3. ping example.comで応答確認。
  4. Test-NetConnection example.com -Port 443でHTTPS確認。
できたか確認

pingが失敗しても443番が成功する場合がある理由を説明できれば完了です。

練習 3

架空の障害を報告する

「Webページが開かない」という想定で、変更せずに情報を集めます。

  1. 発生時刻と対象名を記録。
  2. DNS、443番、サービス、Systemログを確認。
  3. 事実・推測・未確認を分けて3行で報告。
報告例

事実：14:05、名前解決成功、443番失敗。推測：Webサービスまたは通信許可を要確認。未確認：サーバー側サービス状態（権限なし）。

読み取り用PowerShellサンプル
