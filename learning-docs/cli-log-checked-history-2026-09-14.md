本人がWSL Ubuntuでsummarize-log-checked.shを、以前の本人操作のHTTP試験で保存したhistory.logへ適用しました。AIが手順を案内し、本人が提示した端末画像を読み取って公開用要約を作成しています。AIの代理実行やCIの実測ではありません。

| 段階 | 操作 | 提示画面で確認した結果 |

| 対象確認 | findで修正版と履歴を検索 | 各1件、両検索の終了コード0 |

実行の形は次のとおりです。checked_scriptとhistory_fileは、事前に確認した各1件のファイルを指します。

```bash
bash "$checked_script" "$history_file"
echo "修正版の終了コード=$?"
```

今回の終了コード1は「失敗記録あり」という集計判定です。人工サンプルの不正行を検出した際の4とは異なります。今回の履歴は見出し・日時・HTTP応答や本文一致行を含んでおり、形式検査の対象外の行も存在します。

## 制約と未実施範囲

- 形式検査の対象はスクリプト終了コード=で始まる行です。接頭辞の誤字、行の欠落・重複、数値範囲やログ全体の完全性を保証しません。
- 形式検査と集計は別々にファイルを読みます。検査中のログ変更・同時書き込みは未検証です。
- **NOT RUN**：権限不足・同時書き込みの試験、定期実行、自動通知、今回の現在のnginx状態確認。
- 根拠は本人提示画像です。個人環境のIP・ユーザー名・ホスト名・絶対パス、鍵情報、スクリーンショット、ローカル原本、完全な生ログは公開しません。
- ローカル原本のハッシュ照合や、第三者の独立再検証は未実施です。
- 本人が保存した履歴の読み取りと、新しい演習記録の保存を行いました。nginx設定変更・サービス停止は行っていません。
- 静的チェックやCIは文書の検証であり、本人環境での修正版適用の再実行ではありません。

今回の到達点は、形式検査付き修正版が保存済みの実行履歴を集計でき、過去の手動集計・修正前スクリプトと一致することを確認して記録したことです。
