# 実行履歴から失敗を検索

実施日：2026年9月14日（JST）

本人がWSL Ubuntuで、[前回保存した実行履歴](./cli-http-history-2026-09-14.md)から失敗の記録を検索しました。AIが手順を案内し、本人が提示した端末画像を読み取って公開用要約を作成しています。AIの代理実行やCIによる実測ではありません。

今回の対象は保存済みのhistory.logです。新しいHTTP接続やスクリプト実行は行わず、過去の結果を参照しました。

## 本人が実施した操作と結果

| 段階 | 操作 | 提示画面で確認した結果 |
| --- | --- | --- |
| 対象検索 | findで履歴ファイルを検索 | 1件を表示、検索終了コード0 |
| 失敗検索 | grep -nEでスクリプト終了コードが0以外の行を検索 | 15行目にスクリプト終了コード22、検索終了コード0 |
| 状況確認 | grep -nB 5 -Eで一致行の前5行も表示 | 10〜15行目に実行2・日時・curlエラー・HTTP 404・終了コード22。検索終了コード0 |
| 記録保存 | 本人がWSL内に演習要約を保存し、catで再表示 | 保存終了コード0と記録内容を確認 |

検索した条件は次のとおりです。history_fileは事前に確認した1件の履歴ファイルを指す変数です。

```bash
grep -nE '^スクリプト終了コード=[1-9][0-9]*$' "$history_file"
grep -nB 5 -E '^スクリプト終了コード=[1-9][0-9]*$' "$history_file"
```

このパターンは今回の記録形式で、スクリプト終了コードの行全体が正の整数になっているものを検索します。-nは行番号、-B 5は一致した行の直前5行を表示する指定です。検索終了コード0は「一致する行が見つかった」ことを示し、記録されたHTTP処理が成功したという意味ではありません。

## ログから読み取った状況

- 実行2の見出しは「存在しないページ」でした。
- 記録日時は2026年9月14日15:17:56 JSTでした。これは過去の実行前に記録した日時であり、今回の検索時刻ではありません。
- curlのエラーメッセージにHTTP 404があり、HTTPステータス行も404でした。
- スクリプト終了コードは22でした。

今回、終了コードの行だけでなく前の行を読んだことで、どの実行で何が起きたかを確認できました。これは意図的に存在しないURLを要求した過去の練習結果であり、本番障害や新しく検出した接続障害ではありません。
