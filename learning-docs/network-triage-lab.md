# 社内サイトが開けないとき、名前解決とWeb応答を切り分ける

## 受付で何を聞くか

「開こうとしたページと、画面に出たメッセージを教えてください。同じ場所の方はそのページを開けますか。いつまでに、どの作業でお使いですか。」

URLを特定し、本人だけで起きているか、業務を急いで再開する必要があるかを確かめます。以下は、受付後に「サイト名から接続先を調べる段階で止まっているか」を検証する練習です。

## 本人が別の実習で判断したこと

11月20日の机上演習では、Codexが測定し、本人は最初に「アプリの入り口であるnginxが通っているかを確認する」と答えました。入口経由の接続に失敗する一方、内部の稼働確認用ページは応答したため、次に入口への経路を確認すると答えています。11月6日の別のVM実習では、AIの案内で本人が操作し、「HTTP=200、curl終了コード0で復旧と判断した。」と報告しました。[11月20日の本人回答](https://github.com/ns7jp/ns7jp/blob/main/docs/practice-status.md#社内サイトが開けないときの確認)・[11月6日の操作結果と本人の説明](https://github.com/ns7jp/server/blob/main/docs/evidence/2026-11-06-nginx-guided-recovery.md)

## 今回の測定結果

2026年11月20日、CodexがLinux環境で実行しました。検証用Webサーバーは同じ環境の `127.0.0.1` で起動し、通常は名前解決できないテスト用の名前 `portal.invalid` を使いました。プロキシを経由せず、毎回同じファイルを要求しました。

| 順番 | 変えた条件 | 観測した結果 | ここで分かること |
| --- | --- | --- | --- |
| 1 | IPアドレスを直接指定 | 本文 `portal-ok`、HTTP 200、curl終了 0 | 検証用サーバーは指定のファイルを返せた。 |
| 2 | サイト名で通常どおり接続 | `Resolving timed out after 3001 milliseconds`、HTTP 000、curl終了 28 | この要求は名前解決で時間切れになり、HTTP応答を受け取れなかった。 |
| 3 | 同じURLのまま、curlに接続先IPだけを指定 | 本文 `portal-ok`、HTTP 200、curl終了 0 | サイト名と要求先ファイルを保ったまま接続先を渡すと、目的の本文を取得できた。 |
| 4 | 接続先の指定を外し、手順2を再実行 | `Resolving timed out after 3000 milliseconds`、HTTP 000、curl終了 28 | 通常のアクセスは依然として失敗した。手順3は比較用で、復旧とは判定できない。 |

次に調べるのは、この端末が対象の名前をどのように解決するかです。対象は検証用の1台・1ホスト名で、DNSサーバーの故障や他の利用者への影響はこの結果から特定できません。curlの `000` はHTTP応答を受け取れなかったときの表示です。

**利用者への途中連絡の例**　「確認用の端末では、サイト名を使うとページを開けず、接続先を指定した場合だけページが表示されました。普段の開き方ではまだ使えないため、担当者に確認を依頼します。15分後に、進展の有無を含めてご連絡します。」

## 同じ条件で試す手順

LinuxのBash、Python 3、curlを使います。1つ目の端末で以下を実行し、サーバーを起動しておきます。終了時は Ctrl+C で止めます。

```bash
(
  lab_dir=$(mktemp -d) || exit 1
  trap 'rm -f -- "$lab_dir/status.txt"; rmdir -- "$lab_dir"' EXIT
  printf 'portal-ok\n' > "$lab_dir/status.txt"
  python3 -m http.server 18765 --bind 127.0.0.1 --directory "$lab_dir"
)
```

同じ環境の2つ目の端末で次を実行します。環境によっては、手順2と4で時間切れになる前に `Could not resolve host`（curl終了 6）と表示されます。自身の記録にはそのときの表示を残します。

```bash
probe() {
  curl -q --noproxy '*' -sS --max-time 3 -w 'HTTP %{http_code}\n' "$@"
  printf 'curl終了=%s\n' "$?"
}
url=http://portal.invalid:18765/status.txt
probe http://127.0.0.1:18765/status.txt
probe "$url"
probe --resolve portal.invalid:18765:127.0.0.1 "$url"
probe "$url"
```

**本人の追試で残すこと**　今回の名前解決の測定はCodexが実施しました。本人が追試するときは、手順2の表示を見た時点で「次に何を比べるか」「その結果で何が分かるか」を自分の言葉で書き、実際に得た結果と照合します。
