# 中小情シス / 1 人情シス補助 向け追記

「**従業員 50〜500 人規模の中小企業情シス、1 人情シスの補助、コーポレートエンジニア**」ポジションを志望する場合の本ポートフォリオの読み方と、口頭補足のポイントです。

中小情シスは「**何でも屋**」「**コスト最優先**」「**個人技に頼らない仕組み化**」「**業務側との近さ**」に特徴があり、SIer のような分業も SaaS のような専門化もなく、**1 人で全部見る**ことが多いポジションです。

---

## 中小情シスが重視する 6 つの観点

| # | 観点 | 理由 |
|---|---|---|
| 1 | **領域の広さ** | PC キッティングから AD、M365、ネットワーク、サーバー、複合機、業務システムまで |
| 2 | **コスト感** | 高価な商用ツールではなく、Microsoft 365 + OSS + 工夫で運用 |
| 3 | **手順書の継続性** | 自分が休んでも回るように、手順書 + チェックリストを必ず残す |
| 4 | **業務側との距離** | 営業 / 経理 / 製造 の困りごとを聞き、ITで解く |
| 5 | **退職リスクへの備え** | ベンダー依存・属人化を避け、複数人で回せる設計 |
| 6 | **小さな業務改善** | 大規模システム導入より、Excel / PowerShell / Power Automate で日々の作業を 5 分削る |

## 中小情シス特化で追加で言及する点

### 1. 1 人で全部見る = 「何が来ても初動できる」設計

1 人情シスでは「**専門外だから知らない**」が許されません。本ポートフォリオの

- [Linux 一次運用](../../linux-lab.html) → Linux Server も触れる
- [AWS VPC / Terraform](../../cloud-lab.html) → クラウドの基礎も触れる
- [PowerShell 9 本](../../support-scripts/) → Windows / M365 / AD / DB の一次確認
- [物理層](../office-it-physical-layer.md) → ラック / LAN / UPS / 複合機

を**全部 1 人がレビューできる粒度**で書いており、これは「1 人情シスの守備範囲」と完全に一致します。

### 2. 製造・物流 18 年の "現場の困りごとを聞く力"

中小企業の情シスは、

- 営業から「お客さんへのメールが届かない」
- 経理から「会計ソフトのプリンタ印刷が出ない」
- 製造から「ラベル印刷の枚数を 100 枚連続で出したい」

のような**多種多様な相談**を受けます。製造・物流 18 年の現場感があるので、

- **業務の流れの中での困りごと**を聞き取れる
- 「**何が止まると業務が止まるか**」の優先順位を業務側と合意できる
- 改善案を**業務側の言葉で説明**できる

を強みとして提供できます。

### 3. Microsoft 365 を最大限に活用する姿勢

中小企業は M365 で「メール + ファイル共有 + Teams」だけ使っていることが多いですが、

- **Power Automate** で承認フロー自動化
- **Forms + Excel** で簡易申請システム
- **SharePoint Lists** で簡易データベース
- **Intune** で BYOD / Autopilot
- **Conditional Access** でセキュリティ強化
- **Defender for Endpoint** で EDR

まで活用できると、商用ツール導入なしで多くの課題が解決できます。本ポートフォリオの[M365 ポリシー JSON](../m365-policy-examples/) は、その第 1 歩を JSON で示しています。

### 4. 退職を見据えた仕組み化

1 人情シスの最大リスクは「**その 1 人が退職したら誰も触れない**」状態です。私自身が将来そうならないよう、

- 全作業を Markdown / コード / JSON で**外部化**
- 設定変更は GUI ではなく **Git 管理可能な形** (Terraform / Ansible / JSON) で
- ベンダー連絡先 / ライセンス情報 / 機器台帳は**台帳ファイルで一元管理**
- 月次レポートで**「今月何が起きたか」を全社可視化**

を意識します。本ポートフォリオの構造そのものが、この発想で組まれています。

### 5. 小さな改善の積み重ね

「**1 件あたり 5 分削減 × 月 240 件 = 月 20 時間削減**」のような小さな改善を継続するのが中小情シスの王道です。本ポートフォリオの

- [KPI 表](../../README.md#想定-kpi--業務改善見込み架空数値) — 想定削減時間の数値化
- [`New-EndpointDailyReport.ps1`](../../support-scripts/New-EndpointDailyReport.ps1) — 朝のヘルスチェック自動化
- [PowerShell 純関数化 + Pester](../../support-scripts/lib/Triage-Lib.ps1) — テストを書く前提の設計

は、まさに「**小さな改善を仕組み化する**」発想の表れです。

## 入社後 3 ヶ月の進め方 (中小情シス補助想定)

| 期間 | 目標 | 具体物 |
|---|---|---|
| 1 週目 | 物理サーバー / ネットワーク / 主要業務システム / M365 / AD の現状把握 | 現状俯瞰図 (手書きでも) + 質問リスト |
| 2-4 週目 | 既存手順書を通読し、不足分を Markdown 化 | 引き継ぎメモ + 改訂候補リスト P1/P2/P3 |
| 2 ヶ月目 | ヘルプデスク一次受けを主担当 + 月次レポートを自分でも書いてみる | チケット 30 件 + 月次レポート 1 本 |
| 3 ヶ月目 | 業務改善タスク 1 件を主担当 (例: 棚卸し自動化 / 報告書テンプレ化) | PowerShell スクリプト 1 本 + 削減時間の数値化 |

「**派手な技術導入**より、**地味な棚卸しと手順化**」を最優先する想定です。

## 補強したい技術 (応募までに / 入社後に)

| 領域 | 状態 | 補強計画 |
|---|---|---|
| **Power Automate / Power Apps** | 未経験 | 個人テナントで簡易承認フロー / 申請アプリ作成 |
| **Microsoft Intune / Autopilot** | JSON 定義レベル | 個人テナント + 中古 PC で Autopilot 動作確認 |
| **業務システム (会計 / 販売管理)** | 未経験 | 主要パッケージ (奉行 / 弥生 / freee / SAP B1) の概要把握 |
| **ネットワーク機器** | Lab レベル (VLAN / SG / Terraform) | Cisco / YAMAHA / Fortigate の基本コマンド |
| **複合機 / プリンタ** | 物理層ドキュメント | リコー / キャノン / 富士フイルムBI の管理画面 |
| **資格** | ITパスポート (2026-06) | LPIC-1 → CCNA → MS-100 / MS-101 |
