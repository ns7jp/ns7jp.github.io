## 作成した処理

次のコードは会話で案内し、本人の保存操作の画面で確認したものです。ローカル原本を取得してハッシュ照合したものではありません。

```bash
#!/usr/bin/env bash

url="${1:-http://127.0.0.1/}"
expected="${2:-Welcome to nginx!}"

body_file=$(mktemp) || exit 2
trap 'rm -f -- "$body_file"' EXIT

if curl --noproxy '*' --max-time 10 --fail-with-body -sS \
  -o "$body_file" -w 'HTTPステータス=%{http_code}\n' "$url"
then
  if grep -F -- "$expected" "$body_file"
  then
    echo "成功：期待する文字列が本文にあります"
    exit 0
  else
    match_status=$?
    echo "本文確認失敗：検索の終了コード=$match_status"
    exit "$match_status"
  fi
else
  curl_status=$?
  echo "HTTP取得失敗：curlの終了コード=$curl_status"
  exit "$curl_status"
fi
```

第1引数はURL、第2引数は検索文字列です。未指定または空なら既定値を使用します。curl成功時だけgrep -Fで固定文字列を検索し、curl失敗時は本文検索に進まず、その終了コードを返します。

これは文字列の包含判定であり、本文全体の完全一致やHTML構造の検査ではありません。また、HTTP 200だけを許可する明示的な判定は実装していません。今回試した200・404以外の応答を網羅する監視としては未検証です。
